# 第 1 步纪律：五视角独立取证

## 目的

把同一主题拆成五个真正不同的观察窗口，而不是让一个执行者先写共识、再把共识换五种口吻。先分发、后收集；第 2 步之前不得把一个视角的产物发给另一个视角。

## 独立性档位

按 preflight 建议选择并写入 `run-state.md`：

| 档位              | 执行规则                                                      | 降级声明                         |
| ----------------- | ------------------------------------------------------------- | -------------------------------- |
| `parallel`        | 5 个并行 subagent，各自只读主题、自己的原文段和 persona 纪律  | 无                               |
| `serial-isolated` | 5 次串行独立调用；每次写盘前不读其它视角产物                  | 无并行能力，分歧仍保留但延迟收集 |
| `orchestrated`    | 主 agent 顺序完成五段；第 2 步显式写“编排模式·分歧可信度降级” | 不能把编排结果称为独立共识       |

## 视角与渠道

本表同时供脚本机读（角色任务包经 `contract_io.role_channel_table` 消费）：第一列必须精确使用五个角色名，保持「视角 / 先查什么 / 重点追问」三列结构；单元格对齐空格不限。`preflight.py` 会在运行前校验此表可解析。

| 视角     | 先查什么                                      | 重点追问                 |
| -------- | --------------------------------------------- | ------------------------ |
| 实践者   | 工程博客、issue tracker、事故复盘、从业者论坛 | 落地时哪里最容易失效？   |
| 学者     | 同行评审论文、综述、会议录                    | 证据与大众认知哪里相反？ |
| 怀疑者   | 复现失败、负面结果、撤稿、批评、对立长文      | 支持者刻意忽略哪些证据？ |
| 经济学家 | 融资并购、定价、营收、市场规模报告            | 谁从当前叙事获利？       |
| 历史学家 | 相似先例、行业史、失败案例回顾                | 类似规律最后如何收场？   |

## 检索操作要求

把检索当作本角色独立取证，而不是为既定结论找链接。先围绕本角色的`优先渠道`和`重点追问`设计首轮查询；查询应能暴露这个视角特有的证据、反例或利益关系，不能只把主题名称换词。资料不足时再扩大到相邻渠道。不要规定固定检索次数：当证据已足以支撑核心立场、揭示至少一个反例或限制，并能说明未决问题时即可停止。

优先用 AnySearch 发现候选来源。主题明显属于其支持的垂直领域（如学术、金融、医疗、法律、代码或安全）时，先发现可用子域及其必填参数，再选择垂直检索；领域边界不清时，可并行使用一个通用查询与多个角色相关的垂直查询，比较覆盖面后取舍。纯百科式主题可直接使用通用检索。批量查询只用于彼此独立的检索方向，不要为了凑数量重复相近查询。

渠道可读性优先：取证查询优先选择产物为文本的渠道。主题落入 AnySearch 支持的垂直域时，优先文档类子域（如 academic、code.doc、legal、health）；academic 子域可附 `has_pdf=true` 或 `open_access=true`，并用 `year_from` 设定年份倾向，但注意这些是软过滤、不构成保证，候选仍须逐条核对可读性。使用 `social_media` 域时避开 `reddit_media`、`x_media` 等媒体型 `type` 值。

搜索排名和摘要只用于筛选候选，不能单独把主张定为 A/B。优先选择与本角色渠道匹配的原始材料或一手记录；对将用于支撑主张的公开 `http(s)` 候选 URL，先用 jina-reader 读取网页或 PDF 正文。若读取失败、正文截断或缺少目标段落，再用 AnySearch `extract` 复核。正文转换工具不提高来源权威性：始终以原始 URL 归因，并依据实际正文对主张的直接性、完整性评定 A/B/C。不得把含凭据、私有主机或敏感查询参数的 URL 交给正文提取器。

候选出局双判据：候选先按可用性标记、再按 URL 形态筛选。优先核对结果的 `Availability` 行与 `Full Text Links` 中的 `(Open access)` / `(Subscription required)` 标注；标注订阅制的不进入正文提取。URL 形态识别为视频、音频或课程平台（watch、video、episode 类路径）的候选同样出局——AnySearch `extract` 仅支持 HTML 页面。被出局的候选记入检索记录：状态`未采信`，理由注明付费墙或介质不可读。对时效敏感的主张，候选筛选时同时核对发布时间（academic 域结果带 `Published` 字段，网页提取正文常含日期）；显著过旧的在`取舍理由`注明，或出局换更新的候选。

准入线与文本替身：正文不可读的介质（视频、音频、付费墙后内容）不进入证据链、不承载主张、不参与评级；命中的此类来源仅作为线索记入检索记录。确有价值的候选补一次文本替身查询（官方文档、文字稿/transcript、配套文章）；命中文本替身按既有转述规则定级，找不到即放弃。

每次取舍都留下可复核痕迹：记录实际查询词、使用的渠道或子域、结果状态、原始来源 URL 和采信或放弃理由；未命中、工具不可用、提取失败和被排除的候选同样保留。无法取得可验证正文时，不要以搜索摘要或模型记忆补造 URL，按既有未锚定规则降级。

## 每视角产出格式

每份 `perspectives/*.md` 正式角色产物必须包含：

1. `核心立场`：正好两句话，说明这个视角把主题看成什么。
2. `最强证据`：列出主张、来源链接、来源等级 `A/B/C` 和为何采信。
3. `独家洞见`：一件其它视角不会主动说的事。
4. `视角分析`：完整保留主张、反例和限制，不要求隐藏思维过程。
5. `检索记录`：至少一条，保存查询词、渠道、结果状态、来源 URL 和取舍理由；失败检索也保留。
6. `未决问题`：1–3 项，或带可核查理由的无。

检索工具未实测或实测不可用时不要用记忆补 URL：记录“检索不可用”，主张等级统一为 C，并在运行状态设`锚定模式：未锚定模式`。父 agent 等五份文件分别通过角色校验后，才把核心字段逐字抽取到`01-perspectives.md`；完整分析和检索记录不压缩掉。
