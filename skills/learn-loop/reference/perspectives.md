# 第 1 步纪律：五视角独立取证

## 目的

把同一主题拆成五个真正不同的观察窗口，而不是让一个执行者先写共识、再把共识换五种口吻。先分发、后收集；第 2 步之前不得把一个视角的产物发给另一个视角。

## 独立性档位

按 preflight 建议选择并写入 `run-state.md`：

| 档位 | 执行规则 | 降级声明 |
|---|---|---|
| `parallel` | 5 个并行 subagent，各自只读主题、自己的原文段和 persona 纪律 | 无 |
| `serial-isolated` | 5 次串行独立调用；每次写盘前不读其它视角产物 | 无并行能力，分歧仍保留但延迟收集 |
| `orchestrated` | 主 agent 顺序完成五段；第 2 步显式写“编排模式·分歧可信度降级” | 不能把编排结果称为独立共识 |

## 视角与渠道

| 视角 | 先查什么 | 重点追问 |
|---|---|---|
| 实践者 | 工程博客、issue tracker、事故复盘、从业者论坛 | 落地时哪里最容易失效？ |
| 学者 | 同行评审论文、综述、会议录 | 证据与大众认知哪里相反？ |
| 怀疑者 | 复现失败、负面结果、撤稿、批评、对立长文 | 支持者刻意忽略哪些证据？ |
| 经济学家 | 融资并购、定价、营收、市场规模报告 | 谁从当前叙事获利？ |
| 历史学家 | 相似先例、行业史、失败案例回顾 | 类似规律最后如何收场？ |

## 每视角产出格式

每份 `01-perspectives.md` 原始产物必须包含：

1. `核心立场`：正好两句话，说明这个视角把主题看成什么。
2. `最强证据`：列出主张、来源链接、来源等级 `A/B/C` 和为何采信。
3. `独家洞见`：一件其它视角不会主动说的事。
4. `检索记录`：查询词、渠道、命中数、采信/不采信及原因。

检索工具不可用时不要用记忆补 URL：记录“检索不可用”，主张等级统一为 C，并在运行状态设 `anchoring_mode: 未锚定模式`。
