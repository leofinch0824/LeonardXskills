# 第 0 步执行契约：运行状态

## 目的

建立本轮唯一控制状态，保存用户来源、能力降级、阶段游标和实际披露记录。

## 允许消费

无运行目录上游；只消费前置判定、用户画像回答和 `preflight.py --json` 的实际结果。

## 必须产出

`run-state.md`，固定包含：执行契约、消费上游、运行标识、前置判定、学习画像、能力与降级、模式 A 进度、上下文披露记录。

## 结构约束

- 运行标识六字段：运行 ID、创建时间、主题、运行目录、原始提示词文件、原始提示词 SHA-256。
- 主题必须为提炼后的短标题，不超过 10 个字，直接用作首页主标题；完整主题解释保留在原始提示词，由副标题承载范围补充。
- 前置判定四字段：判定、判定理由、调整说明、资料探针。
- 学习画像五字段：当前水平、目标深度、角色 / 使用场景、画像句、默认处理。
- 能力与降级五字段：独立性档位、子 agent 验证依据、锚定模式、检索验证依据、降级声明。
- 模式 A 进度三字段：当前阶段、已完成阶段、生成状态。
- 每个上下文披露记录只含准备时间和披露清单。
- 不保存考试游标、弱项、施考状态或费曼状态。

## 内容评审

用户来源、能力实测依据和调整后适合的确认原话必须真实；执行模型不能自证。

## 允许为空的条件

无披露记录时写“无：尚未准备模式 A 阶段”；其他字段不得为空。

## 完成条件

状态字段唯一、枚举合法、运行标识可追溯，且不存在重复事实源。
