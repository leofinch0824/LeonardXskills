# 第 0 步执行契约：运行状态

## 目的

建立本轮唯一控制状态，保存用户来源、能力降级和阶段游标。

## 允许消费

无运行目录上游；只消费前置判定、用户画像回答、`preflight.py --json` 的实际结果与诊断探针检索发现。

## 必须产出

`run-state.md`，固定包含：执行契约、消费上游、运行标识、前置判定、学习画像、能力与降级、模式 A 进度。

## 结构约束

- 运行标识六字段：运行 ID、创建时间、主题、运行目录、原始提示词文件、原始提示词 SHA-256。
- 主题必须为提炼后的短标题，不超过 10 个字，直接用作首页主标题；完整主题解释保留在原始提示词，由副标题承载范围补充。
- 前置判定四字段：判定、判定理由、调整说明、资料探针。
- 学习画像六字段：当前水平、目标深度、角色 / 使用场景、画像句、默认处理、诊断探针。
- 来源标记按字段分级：`当前水平`与`角色 / 使用场景`的终态前缀唯一为`用户回答：`（草稿期可标`推断待确认：`，校验时被拦）；`目标深度`允许`用户回答：`、`用户开场已提供：`、`推断待确认：`、`未提供`。
- 证据标准：目标深度须是带范围的目标；当前水平须是覆盖领域整体的自评，单点信念与间接信号不算；角色 / 使用场景须是明确的动作陈述。
- `用户开场已提供`（仅目标深度）须逐字对应开场原文；`推断待确认`内容为推断值＋一句依据，存在时阶段 0 不得通过。
- 默认处理两分支：无缺失时写`无需默认值`；有`未提供`或用户授权默认时写`已按默认值执行：<实际默认值>`，须可回溯用户授权原话。
- 诊断探针格式：`未执行：<理由>` / `已执行：<两方向要点> → 确认问题（逐条一行，注明对应画像字段与探针依据）`。
- 能力与降级五字段：独立性档位、子 agent 验证依据、锚定模式、检索验证依据、降级声明。
- 检索验证依据须注明端到端实测内容：一次成功检索与一次候选正文成功读取。
- 模式 A 进度三字段：当前阶段、已完成阶段、生成状态。
- 不保存考试游标、弱项、施考状态或费曼状态。

## 诊断探针协议（画像锁定前）

- 触发：`prepare_stage.py --stage 0` 物化 run-state.md 并读取本契约之后、学习画像字段终填之前（阶段 0 窗口内）；允许带`推断待确认`草稿进入阶段 0。区别于前置判定的资料探针（判资料密度、服务判定结论）：诊断探针校准画像确认问题、服务阶段 0。
- 规模：至多 4 次检索、分钟级；不得使用 subagent 取证规模。检索能力此时已经 preflight 验证；探针检索不充当检索验证依据（时序上亦不可能）。
- 必检两方向：
  1. 领域决策空间：该主题的主要子问题/维度——用于判断需求陈述是否把多个子问题压成一句，澄清式问题优先归属目标深度或角色 / 使用场景。
  2. 误解分布与水平信号：该领域哪些误解跨水平普遍存在（零诊断力信号）、区分水平层级通常看什么——用于判断开场信号的定级诊断力，并生成定级式确认问题。
- 产物：确认问题清单，逐条一行、注明对应画像字段与所依据的探针发现，记入`诊断探针`字段；可随问题向用户展示依据以校准。目标深度达标时其确认问题可为 0 条；当前水平与角色始终至少各一条 recap 确认（锁定权规则）。
- 边界：不进 A/B/C 证据链、不产生来源记录、不单独定级；可与资料探针共享发现；检索失败时记`未执行：<理由>`，问题退化为通用问题，问询义务不变。

## 内容评审

用户来源、能力实测依据和调整后适合的确认原话必须真实；执行模型不能自证。`用户开场已提供`须能逐字回溯开场原文；改记的`用户回答：`须能回溯批量确认问答；`已按默认值执行：`须能回溯用户授权原话——三项均列入交付时用户复核清单。探针发现不得用于替代问询或单独定级。

## 允许为空的条件

其他字段不得为空。

## 完成条件

状态字段唯一、枚举合法、运行标识可追溯，且不存在重复事实源；画像两高危字段以`用户回答：`收尾且无未确认推断残留。
