# HTML 渲染指南

## 事实源和模板

由[`scripts/render_learning_page.py`](../scripts/render_learning_page.py)在全部 Markdown 阶段通过后读取事实源、静态构建[`assets/template.html`](../assets/template.html)，再调用`render_template.py`打包固定资源。不要让 agent 手工拼接占位符。交互层（三态自评、进度、搜索、章内目录、连续学习导航、对话交接和打印）由`assets/template.js`在浏览器运行时注入，生成物源码不携带用户表现。模板通过相对路径加载`template.css`与`template.js`；用户打开 HTML 不依赖网络，也不在浏览器 fetch Markdown。仅在需要物理单文件时使用`--inline`。

`{{RUN_ID}}` 必须填为本轮运行目录的稳定 slug（例如 `2026-08-03-143052-python-asyncio`），不要使用页面标题。它只用于隔离浏览器本地阅读和自评状态，不写回 Markdown；标题修改后本机状态仍可延续。模板 JS 会尝试读取旧版标题键一次，兼容已有本地状态。

## 阅读序不等于生成序

生成按 1→10 严格顺序执行，但页面是给人学的视图：侧栏与 section 顺序为「学习地图 → 10 速查 → 07 课程 → 06 阶梯 → 09 费曼 → 08 自测 → 01–05 取证 → 收尾」。先给结论和可操作内容，再给论证过程。不要把 section 改回流水线顺序。

## 双层信息架构

每个 step section 的默认可见层只有：页面上的「这一页，先记住这些关键词」提示区、可视化（如有）、产物正文。提示词原文和「消费上游」一律放进章节末尾的 `<details class="panel evidence">`，**不加 `open`**，摘要固定为「取证 · 提示词与上游」。取证是溯源材料，不与教学内容争夺视觉权重。

页面样式采用“证据驱动的学习工作台”：桌面宽屏显示全局目录、主阅读列和章内上下文栏；窄桌面自动收起第三栏。布局、断点和交互都在固定 CSS/JS 中，渲染者不生成第三栏内容。本版不要求渲染者为移动端准备另一份内容或结构，小屏只保留既有内容可达降级。

## 总览主标题层级（必须）

总览页的首标题必须保持“短主标题 + 小号副标题”的层级，不能把完整主题作为一段纯文本塞进 `<h1>`。固定模板已经提供结构：

```html
<h1 data-od-id="topic-title">
  {{TOPIC}}
  <span class="h1-sub">{{TOPIC_SUB}}</span>
</h1>
```

- `{{TOPIC}}` 是开头的短主标题，通常保留 2–8 个字/词，使用展示字号突出主题核心。
- `{{TOPIC_SUB}}` 是主题的范围、方法或场景补充，必须非空，使用 `.h1-sub` 的较小、低饱和样式。
- 两个占位符分别做 HTML 转义；不要把 `<span>` 写进占位符内容，也不要用 `<br>` 或内联 `style` 模拟层级。
- `<title>` 可以同时包含两个占位符，但页面语义上只能保留一个 `<h1>`；主标题和副标题不得重复同一段文字。
- 生成后必须检查最终 HTML 同时存在 `data-od-id="topic-title"` 和 `.h1-sub`，不能只检查占位符已经被替换。

章节标题由模板 kicker 显示步骤编号，因此 `{{STEP_N_TITLE}}` 优先填简洁主题，例如「五分钟速查表」，不要再次写「第 N 步：」。标题宜在桌面两行内；过长时保留准确含义，不用省略号裁切。

## 章节语义与专属模块

模板为各视图固定 `data-module`，分别对应 `reference`、`practice`、`ladder`、`teach`、`recall`、`perspectives`、`conflict`、`brief`、`review`、`resources`。渲染者继续填既有槽位，不需要读取或生成这些样式逻辑。

- 第 1 步五视角继续使用 `.persona-grid > .persona`。概览卡必须链接到对应正文锚点（`#persona-实践者`、`#persona-学者`、`#persona-怀疑者`、`#persona-经济学家`、`#persona-历史学家`）；正文角色标题使用相同 id。固定样式会为五种角色赋予低饱和的区分色，并以更大的标题呈现。
- 第 2 步把实质分歧、措辞分歧和未决问题保留为独立标题组，避免合并成一个长列表。
- 第 3 步 CEO 摘要必须是正文第一个三级标题后的段落，固定样式会将其呈现为执行摘要。
- 第 6 步继续使用 `.ladder > .rung`，阶梯层级由顺序和缩进表达，不另加装饰图片。
- 第 8/10 步只使用 `.deck > .flash`；模板 JS 注入练习工具条与三态自评。
- 第 5 步来源链接保留可解析 URL；固定样式会为外部链接添加可见提示。
- 正文表格继续使用 `.table-wrap`；固定样式保留轻量横向行线，并为相邻列添加低饱和竖向分隔线。不要在渲染片段中手写单元格边框。

所有用户可指出的重复模块应使用稳定、唯一、kebab-case 的 `data-od-id`。HTML `id` 继续承担锚点与组件身份，二者都不得重复。

## 取证块必须是"已填提示词"

`{{STEP_N_INPUT}}` 放的是**本轮实际执行的提示词**，不是 `original-prompts.md` 的空白法条。渲染前按 `run-state.md` 的学习画像把 `{{主题}}`、`{{角色}}`、`{{水平}}`、`{{目标}}` 代入真实值；值为 `未提供` 的槽位按 run-state 中的默认值代入，并在该取证块开头注明"该槽位按默认值执行"。不得在 HTML 中保留 `{{槽位名}}` 字面量。

提示词进 `<pre class="text"><code>` 时**只做一次 HTML 转义**。不要为了躲开模板替换而把花括号预先写成 `&#123;`——那样再经一次转义就变成 `&amp;#123;`，页面上会显示成一串实体码而非占位符。若确需保留未填槽位的字面量，用 `<span class="slot">` 包裹原样花括号，替换引擎只认 `{{大写英文}}` 形式的模板占位符，中文槽位不会被误伤。

## 答案必须可折叠

第 8 步题库和第 10 步快问快答用 `.flash` 组件渲染，题干在 `<summary>`，参考答案与评分标准在 `.flash-answer` 内，默认收起：

```html
<details class="flash">
  <summary><span class="level">初级</span>题目 1：用自己的话解释 …</summary>
  <div class="flash-answer">
    <p><strong>参考答案：</strong>…</p>
    <p><strong>评分标准：</strong>…</p>
  </div>
</details>
```

任何 `参考答案`、`评分标准`、快问快答的答案都不得出现在 `.flash-answer` 之外，否则主动回忆失效。第 10 步快问快答的题目和答案都必须取自 `10-cheatsheet.md` 事实源，HTML 只渲染、不得在视图层补写答案。

自评按钮由模板 JS 注入 `.flash-answer` 末尾，保证学习者先展开并对照答案，再标记「掌握 / 模糊 / 未掌握」。重复点击当前状态可撤销；「只看薄弱项」包含模糊、未掌握和未练习题。不要在渲染片段中手写自评按钮。

## 交互层与状态边界

- 闪卡自评和章节已读只存本机浏览器；自评固定提示「本机练习，不计入真实施考记录」。存储不可用时退化为当前页面会话的内存状态。
- 自评/已读不是模式 B/C 的答题或复述记录，不进入任何 Markdown 事实源，不得写回 HTML 源码，也不得改变施考状态行。
- 洗牌只通过 CSS `order` 改变本轮显示顺序；筛选只隐藏已掌握卡片。两者都不得改变题库事实源或生成物中的 DOM 顺序。
- 搜索遍历全部视图并跳转定位；打印展开全部视图和折叠内容；禁用 JS 时由 `<noscript>` 平铺全部视图。这些能力不增加渲染占位符。
- 第 8/9 步状态区由 JS 增加“复制提示词”按钮，只把「考我 <主题>」或「给我讲 <主题>」复制到剪贴板；它不在静态页面内模拟 AI 会话。
- 连续学习导航按 HTML 中的阅读顺序运行；普通章节的章内目录只取当前 `.prose > h3`，不混入次级 `h4`。第 1 步五视角例外，只取带 `persona-` 锚点的五个角色标题。目录不再按 DOM 顺序截断，不增加内容槽位。

## 占位符清单

| 占位符 | 内容 |
|---|---|
| `{{RUN_ID}}` | 稳定运行目录 slug；仅作为浏览器本地状态命名空间 |
| `{{TOPIC}}` | 总览页短主标题（HTML 转义） |
| `{{TOPIC_SUB}}` | 总览页副标题/范围补充（HTML 转义，必须非空） |
| `{{EXAM_STATUS}}` / `{{FEYNMAN_STATUS}}` | 从模式 B/C 记录文件存在性与会话状态静态推导；浏览器不读取 Markdown |
| `{{METHOD_INTRO}}` | 方法和学习画像的总览段 |
| `{{STEP_MAP}}` | 10 个步骤导航卡；数字已由 `.step-number` 显示，卡片标题不要重复「第 N 步」 |
| `{{STEP_N_TITLE}}` / `{{STEP_N_PURPOSE}}` | 第 N 步标题与用途 |
| `{{STEP_N_INPUT}}` | 已填原文提示词与消费上游标签（进取证折叠） |
| `{{STEP_N_OUTPUT}}` | 完整原始产物片段，**剥去「本步提炼」小节** |
| `{{STEP_N_TAKEAWAYS}}` | Markdown「本步提炼」中的恰好 3 条结论；在页面「本章要点速览」提示区唯一呈现 |
| `{{STEP_N_VIZ}}` | 语义可视化；无内容时留空，CSS 自动隐藏空槽 |
| `{{STEP_8_CARDS}}` | 10 道题的 `.flash` 卡片（替代第 8 步 OUTPUT 正文） |
| `{{STEP_10_QUIZ}}` | 快问快答的 `.flash` 卡片（题目与答案均取自 `10-cheatsheet.md` 事实源） |
| `{{CLOSING_INTRO}}` | 从开局到压缩的闭环回顾 |
| `{{CLOSING_DELIVERABLES}}` | 事实源、题库、讲解、速查表和练习入口 |
| `{{LOOP_DIAGRAM}}` | 收尾闭环图 |

`{{STEP_N_OUTPUT}}` 必须剥离产物里的 `## 本步提炼` 小节——该内容只经 `{{STEP_N_TAKEAWAYS}}` 呈现一次，重复渲染会产生重复 `id` 和冗余阅读。第 8 步没有 OUTPUT 槽位，题目全部走 `{{STEP_8_CARDS}}`。

## 可视化与去重

第 1 步用五视角卡片，第 2 步用冲突/共识关系图，第 6 步用阶梯。其余步骤 `{{STEP_N_VIZ}}` 留空即可，`.viz:empty` 会隐藏空框，不要为凑格式输出空白装饰。同一结论骨架不在多个 section 用近乎相同措辞复述；后续 section 引用前文时用一句话回指，不整段重抄。

## 交付前检查

生成后确认 `{{` 不再出现，并确认 `<noscript>` 降级、非空 `data-run-id`、工作台关键区域和每个 `.view` 的唯一 `data-od-id` 仍存在。运行时交互不产生新的事实内容填充义务。第 8/9 步保留状态行「交互施考未进行，对我说"考我"即可开始」或「交互施考已完成 N 题」「交互费曼会话未进行……」，不能把参考答案、讲解材料或本机自评误标为用户表现。施考状态行只有这两种合法形态；用户练习后重渲染时以 `08-exam-record.md` 的 `当前游标` 为依据，费曼结束状态仍以 Markdown 记录为依据。

结构闸门由 `validate_stage.py --stage html` 检查：占位符残留、`<noscript>` 降级、稳定 run id、工作台关键区域、施考状态行、答案是否在 `.flash-answer` 内、取证折叠是否默认收起、`id`/`data-od-id` 是否重复、每个视图的 inspectable 标记以及`本步提炼`是否重复渲染。空 `.viz` 由 CSS 隐藏，不单独设闸门。

维护固定资源时，`template.js` 和 `template.css` 内每个 `}` 必须单独成行，禁止连续 `{{` 或 `}}`；占位符残留闸门是文本检查，连续花括号会被误判为未渲染占位符。agent 无需读取或修改这两个文件，只填 HTML 中的内容槽位。
