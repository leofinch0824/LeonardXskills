# 第 2–4 步纪律：冲突、综合与自检

## 冲突分类

- **实质分歧**：两个不兼容结论，双方都能拿出 A/B 来源。进入冲突图谱，并列出双方证据。
- **措辞分歧**：结论相同，只是范围、语气或术语不同。记录后从主要冲突图剔除。
- **未决**：至少一方没有 A/B 来源，或证据无法直接支持结论。单列为待验证，不伪装成冲突。

## 共识与盲区

只有“至少两个视角 + 不同来源 + 至少一条 A/B”才能标`独立共识`。各视角一致但全部为 C 时标`模型先验·待验证`。全体一致必须有五个支持视角，局部一致必须有 2–4 个；两组可以同时出现，但同一结论不得重复归类。

“没有任何视角提到”只有在五份 `检索记录` 都已落盘后才可标 `领域盲区`；没有记录只能写 `未覆盖`，并说清缺失哪类检索。

## 第 3 步综合

每个关键发现保存证据引用、综合等级、支持视角、反对视角。`anchored`输出综合简报，前三项必须为 A/B；`未锚定模式`输出假设简报，五项统一为 C 并声明模型先验。60 秒 CEO 段保持一个连续段落，覆盖结论、依据、不确定性和行动含义。行动建议必须代入用户角色并给出可观察完成信号；前沿问题必须说明为什么会改变整体理解。

## 第 4 步可靠性推导

不要凭感觉打分。采用以下可复查规则并写出计算理由：

- 9–10：至少两条不同的一手 A 来源，无实质反驳。
- 7–8：一条 A 加一条 B，或多条 B 且范围一致，反驳可解释。
- 5–6：仅一条 B、来源间有未决差异，或关键条件未验证。
- 3–4：主要依据为 C，或实质分歧未裁决。
- 1–2：只有模型先验、来源错配或与已知 A 来源冲突。

分数可以在区间内调整，但必须写来源数量、等级、分歧类型和还缺什么证据。第 6 视角要回答“加什么会改变结论”；确实没有时给出可核查的审查理由。步骤 4 只引用步骤 3 的发现，HTML 构建时再静态展开原发现，不在 Markdown 里重复抄写。
