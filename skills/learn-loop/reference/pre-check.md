# 前置判断纪律：适用性判定与意图拆解

## 目的

在用户给出学习主题之后、任何初始化（preflight、能力实测、run-dir 创建）之前，回答一个问题：**这个目标值不值得、适不适合用十步闭环来学**。前置判断是 skill 的「门」，不是流水线的第 0 步：它不做开场画像（画像三问仍在模式 A 照常执行），只产出判定结论并决定走向。

## 触发时机

- 用户给出新学习主题时，必做一次。
- 同一轮对话中用户更换主题，重新做一次。
- 模式 B/C（考我 / 给我讲 / 我来讲）不触发前置判断——它们消费已有 run-dir。

## 判定结论只有三种

| 结论       | 含义                             | 走向                                           |
| ---------- | -------------------------------- | ---------------------------------------------- |
| 适合       | 信号通过，无需调整               | 移交初始化与开场画像                           |
| 调整后适合 | 调整范围/边界/声明风险后可用     | 用户确认调整方案后移交                         |
| 不适合     | 十步闭环不是达成该意图的合适路径 | 不建 run-dir、不跑 preflight，直接交付替代路径 |

用户明确坚持对「不适合」主题执行时，尊重其选择：转为「调整后适合」，在调整说明中记录原判定与已向用户声明的风险。

## 适用性信号

**正向信号**（越多越适合）：

- 主题是知识域/学科/技术体系，而非单一事实点（「分布式事务」✓，「Redis 默认端口」✗）。
- 用户要可留存、可复习、能考核的掌握，而非一次性答案。
- 主题存在可检索的公开资料（工程博客、论文、文档、行业报告）——五视角取证是这套方法的地基。
- 用户接受以小时计的生成成本与多轮交互。

**负向信号**（命中任一即进入意图拆解）：

- 只要一个事实、一个定义、一段代码的即时答案。
- 真实意图是决策（「我该学 A 还是 B」）或产出（「帮我写个方案」），学习只是手段。
- 主题以身体技能/默会知识为主（游泳、绘画手感、谈判临场）——文本检索练不出肌肉。
- 主题过于前沿或私密，公开资料近乎为零（强行执行只会全链路降级为 C 级模型先验）。
- 范围过大无边界（「学计算机科学」）或过小撑不起五视角（「学某 API 的一个参数」）。
- 有硬截止时间且来不及跑完整流水线。

## 反问清单（信号不足时，最多 3 问）

按优先级，缺什么问什么：

1. **用途**：「学完之后你第一件事想拿它做什么？」——区分掌握型/决策型/产出型意图，最关键的一问。
2. **时限与投入**：「你期望多久内能用上？能接受一套需要多轮交互的系统学习流程吗？」
3. **边界**：「这个主题里你最关心的是哪一块？」——用于范围过大的主题收敛。

纪律：用户开场已答的不问；用户说「你看着办」时按默认判断继续，但必须显式声明「已按默认判断执行」。

## 意图拆解决策树

命中负向信号时按下表拆解。铁律：**替代方案必须贴着原始意图，只换路径不换目的地**；每条替代路径用一句话说清「为什么这比十步闭环更适合你现在的目标」。

| 命中的信号                       | 替代路径                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 单一事实/即时答案                | 直接回答；末尾附一句「若想系统掌握 X，可以走十步学习法」                                               |
| 决策型（选 A 还是 B / 要不要学） | 先做对比分析帮其决策；决策落定后再问「要不要对选定方向系统学一遍」                                     |
| 产出型（写方案/做项目/修 bug）   | 直接帮做；过程中提炼「这背后的知识体系是 X，感兴趣可系统学」                                           |
| 技能/默会类                      | 拆成「理论内核 + 刻意练习计划」：理论部分（原理、错误模式、训练方法论）走 skill；明说 skill 管不了手感 |
| 范围过大                         | 收敛到第一个有边界的模块（「学 CS」→「先用十步法攻数据结构与算法基础」），后续模块排成路线图           |
| 范围过小                         | 上卷一层到能撑起五视角的最小主题（「学 gather 的参数」→「学 asyncio 并发模型」）                       |
| 资料稀缺/过于前沿                | 两条路：(a) 用户提供内部资料以此为锚；(b) 声明将进入未锚定模式、全链 C 级，用户知情选择                |
| 硬 deadline 来不及               | 先交付「核心 20%」速览解燃眉之急；完整闭环作为 deadline 之后的可选项                                   |

## 可选：资料探针

主题看似冷门、资料密度存疑时，可在判定前做 1–2 次试探性检索，确认是否存在足量公开资料。这是轻量预判，不计入「路径与初始化」的能力实测，也不产生 A/B/C 来源记录。做过就在移交时把结论写入 `run-state.md` 的「资料探针」字段；没做就填「未做」。

## 交付与移交格式

判定结论统一用三行交付给用户：

```
判定：适合 / 调整后适合 / 不适合
理由：<命中的信号，一句话>
下一步：<移交画像 / 调整方案 / 替代路径>
```

判定移交模式 A 时，把四字段写入 `run-state.md` 的「前置判定」节：判定、判定理由、调整说明（适合时填「无需调整」）、资料探针。任何降级（未锚定、orchestrated、范围收窄）必须显式记录，不得隐性降级。画像补齐与诊断探针纪律由模式 A 阶段 0 契约承载；资料探针判资料密度、诊断探针校准确认问题，二者不互相替代。

## 红线

- 不得跳过前置判断直接初始化；也不得以前置判断为由拖延回答用户的简单问题。
- 不得为留住用户把「不适合」硬判为「适合」；判定真实性属信任型事项，交付时列入用户确认清单。
- 不得替 skill 做开场画像；画像字段缺失的阻塞/默认规则仍由模式 A 自己执行。
- 「不适合」判定下不得创建 run-dir、不得执行 preflight——半成品运行目录比没有更糟。

## 话术示例

- 适合 → 「这个目标适合十步闭环。开始前确认下你的情况——（移交开场画像）」
- 范围过大 → 「『系统学 AI』一次闭环装不下。建议第一期收敛为『大语言模型原理与微调入门』，跑完后把多模态、Agent 等排成后续路线图，可以吗？」
- 决策型 → 「你现在的核心问题是选型而不是掌握。我先给你一份 A/B 的对比结论；定了方向之后，再用十步法系统学选中的那个，这样不浪费一轮完整流程。」
- 技能类 → 「『学吉他』的手感部分文本教不了。这套方法能帮你系统拿下乐理、常见错误和训练方法论这部分理论内核，实操我再配一份四周刻意练习计划，这样组合行吗？」
- 资料稀缺 → 「这个方向公开资料很少，硬跑会退化成我的猜测汇编。两个选择：你提供内部资料我以此为锚；或者我声明全程 C 级未验证，你知情后继续。」
