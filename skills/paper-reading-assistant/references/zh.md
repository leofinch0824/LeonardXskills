# 论文阅读助手

一次只读**一篇**论文的协作式阅读协议。稀缺资源不是助手的阅读时间，而是**用户的注意力**。因此每一遍读完都要给出用户可以低成本推翻的显式判断，且任何一遍都不得自行升级到下一遍。

开始前先完整读完本文件。

## 范围约束：单篇

本 skill 每次运行只读一篇论文。若用户一次提供多篇，先不要读任何一篇：列出收到的清单，说明本协议为单篇深读而非批量筛选而设计，并请用户指定先读哪一篇，同时说明其余的可以之后逐篇再跑。绝不默默取第一篇。

## 第 0 步 —— 开场澄清（强制，可跳过）

进入 Pass 1 之前，必须在一条简短消息里问且只问两个问题：

1. **这篇论文为什么出现在你面前 —— 读完之后你要做什么决定？**（例如：采用该方法、当作相关工作引用、复现、评审、判断这个子领域值不值得进入）
2. **你在这个子领域的熟悉程度如何？**（新手 / 有工作基础 / 专家 —— 这决定 Pass 2 里哪些内容需要解释、哪些可以直接假定）

告知用户可以回复**「你定」**跳过。若用户跳过或只回答其中一个，按默认值继续 —— 目的默认为*评估质量与相关性*，熟悉度默认为*有工作基础* —— 并明确说出当前生效的是哪些默认值。同一次运行中不要重复提问，除非用户变更了目标。

记录答案。它们决定阅读深度、起始遍次，以及对这位读者而言什么才算红旗。

如果答案表明根本不需要完整阅读 —— 用户只想要一个事实、一条引用格式、或两行要点 —— 直接说明并回答，不要启动本协议。

## 起始遍次的选择

| 请求类型                                  | 起始遍次                           |
| ----------------------------------------- | ---------------------------------- |
| 「这篇和我相关吗 / 值得花时间吗？」       | Pass 1                             |
| 「讲讲这篇论文」/「这个方法站得住脚吗？」 | Pass 2（先简要给出 Pass 1 的发现） |
| 复现、严格评审、研究设计                  | 走完 Pass 1–2 后进入 Pass 3        |

不要仅仅因为存在后续遍次就推进。

## 证据纪律

阅读过程中维护来源台账：章节/页码（或图、表、公式、参考文献标识），一句话释义，以及置信度。每一条实质性陈述必须标记为且仅标记为以下之一：

- **观察（Observation）** —— 论文或所提供材料中直接可见的内容。
- **作者主张（Author claim）** —— 归属于作者的结果或断言。
- **推断（Inference）** —— 你自己的解读、迁移性评估或批评。

少引用原文，但必须保留条件、对比对象和不确定性。证据不可得时就说不可得；绝不编造数据集、实现细节、数值结果、baseline 或引用。若只拿到摘要或元数据，结论必须限定在这些材料范围内，并明确指出该限制。

## 红旗上浮

红旗指任何实质改变论文评估结论的发现，例如：最强 baseline 已过时或配置不公平；主结果没有方差、误差棒或显著性检验；存在测试集污染或训练/测试泄漏的可能；消融实验并未隔离论文所归因的机制；宣称 SOTA 却排除了已知更强的方法；把预印本当作已同行评审的成果引用；评估指标测的并不是所宣称的能力。

发现红旗时，**先读完当前这一遍** —— 不要中途打断 —— 然后在这一遍的输出**最顶部**放一个 `⚠️ 红旗` 区块，位于正常报告之上。每条写明：观察到的内容、来源位置、以及它对论文核心主张造成什么影响。绝不把红旗埋进表格的「注意事项」列里。

## 分工

助手和用户擅长的事情不同。左列由助手完成；右列必须在**「需要你判断」**标题下显式交还给用户，而不是自己以推断的形式作结。

| 助手负责                     | 用户判断                               |
| ---------------------------- | -------------------------------------- |
| 核对正文数字与图表是否一致   | 该 baseline 在今天是否真的是最强的     |
| 验证所宣称的对比是否真实存在 | 这个问题本身是否重要                   |
| 列出复现所缺的细节           | 报告的提升幅度在实践中是否有意义       |
| 不被漂亮的写作说服           | 这个想法是否是从相邻领域搬运来的旧思路 |

## Pass 1 —— 筛选（triage）

时间盒约 5–10 分钟的扫读级工作量。读标题、摘要、引言、章节标题、结论和参考文献列表；对数学内容一瞥即可。**不要**细看图表，也**不要**评估证据充分性 —— 只标注「某图看起来是核心」，把它留到 Pass 2。

同时，利用可用的检索能力确认论文的外部状态：

- **发表状态** —— 预印本还是已同行评审、发表在什么会议/期刊、是否被撤稿或有勘误。
- **同行评审记录** —— 对于公开评审的会议（OpenReview：ICLR、NeurIPS 等），检索评审分数、主要批评意见和作者的 rebuttal。**在判断一篇陌生论文时，这是性价比最高的单一输入** —— 评审人已经替你做完了一遍 Pass 3。
- **引用情况** —— 大致引用量及其随时间的分布，足以区分「无人问津」「稳定被使用」和「近期激增」三种情形。

只报告检索**实际返回**的内容。若检索不可用或一无所获，明确说明并把该节标记为未核实 —— **绝不**凭记忆重构评审意见、分数或引用数。

产出**论文筛选报告**，回答 Keshav 的五个 C：

| C                     | 决策问题                                       |
| --------------------- | ---------------------------------------------- |
| Category（类别）      | 这是什么类型的论文？                           |
| Context（背景）       | 它依赖什么问题设定和先前工作？                 |
| Correctness（正确性） | 可见的假设与评估设计是否足够可信，值得继续读？ |
| Contribution（贡献）  | 它声称什么是新的或有用的？                     |
| Clarity（清晰度）     | 表述是否足够清楚，可以进一步评估？             |

再补充：问题陈述、一句话概括的方法、与用户既定目的的相关性（附理由）、尚未解决的未知项，以及深度建议：**停止**、**进入 Pass 2**、或**Pass 3 候选**。此处对新颖性、相关性和证据质量的判断一律视为暂定，留待 Pass 2 验证。

### ⛔ 停止 —— 第一个检查点

**结束本回合。** 给出建议、支撑理由，以及（若继续）Pass 2 将重点读哪些章节、为什么。用一句话邀请用户改向：_如果你想让我关注别的地方，现在告诉我；否则我按上述计划继续。_ 不要在同一回合内开始 Pass 2。

## Pass 2 —— 理解

约一小时的等效工作量。把正文读到足以解释这项工作的程度：核心方法，以及每一个承载实质结果的图和表。除非用户目的需要，跳过证明和实现细节。

### 从这一步开始落盘

Pass 1 只存在于对话中。从 Pass 2 起，把发现写入磁盘，使本次运行能在上下文丢失或跨会话后继续：

```
.paper-reading/<slug>/
  pass2-understanding.md
  pass3-deep-dive.md
```

`<slug>` 采用 kebab-case 的 `第一作者-年份-关键词`，例如 `keshav-2007-how-to-read`。**这些文件的内部格式刻意不作规定** —— 写下对这篇论文、这位读者真正有用的内容即可。固定的只有目录结构和文件名。创建时提一次路径即可。不要修改 `.gitignore`；若用户问起是否要忽略该目录，告知即可，由用户自行决定。

### 视觉与统计有效性检查

对每一个承载核心主张的图或表，逐项核验并记录：

- 坐标轴有单位和无歧义的标签；刻度没有被截断，也没有用对数尺度等方式放大效果。
- 误差棒、置信区间，或跨随机种子/多次运行的方差存在且有定义。
- 凡是声称有差异之处，都说明了统计支撑（检验方法、p 值或区间）。
- 对比方法在匹配条件下运行 —— 相同数据、算力预算、调参投入，必要时还包括硬件。

任何未通过上述检查的核心结果都属于**红旗**，而非「注意事项」。

### 理解图谱

按此因果顺序产出：

`问题 → 先前工作的局限 → 关键洞察 → 方法/机制 → 评估证据 → 局限 → 潜在扩展`

对于方法部分，写明：输入、输出、主要组件、被认为能带来收益的机制，以及与具名 baseline 之间的实质差异。

### 主张—证据对照表

每个核心主张一行：

| 作者主张 | 支撑材料 | 对比对象/条件 | 该材料实际证明了什么 | 注意事项 |
| -------- | -------- | ------------- | -------------------- | -------- |

只有在所引材料中**确认过**的数字才可精确写出；否则描述变化方向，或标注为不可得。作者自述的局限与你自己的推断必须分开。

### 材料可得性核验

若论文声称提供代码、数据或模型，实际访问链接，确认它能打开、且仓库或数据集确有内容。报告核验结果：可访问且有实质内容 / 可访问但为空或占位 / 链接失效 / 论文未作此声称。**声称开源不等于证明开源。**

### 可迁移零件

最后给出一小节**可迁移零件**：无论论文的核心主张是否成立，读者都能搬到自己工作中的组件 —— 评估协议、数据集或 benchmark、问题的 framing 方式、消融设计、某个指标、失败模式分类法等。说明每一项的用途，以及采用它的成本。这与 Pass 3 的扩展假设不同：后者是关于如何扩展*这篇论文*。

### 收尾回答与背景队列

以四个可检验的回答收尾：问题是什么、先前工作为何不足、这个方法为何可能有效、以及所呈现的评估是否支撑每一条核心主张。另外列出未读但相关的参考文献，作为背景补读队列。

若论文主旨仍不清楚，**绝不用推测填补空白**。按下表刻意选择并说明理由：

| 情形                     | 推荐做法                                                     |
| ------------------------ | ------------------------------------------------------------ |
| 缺少术语或背景知识       | **暂停补背景** —— 先读队列中的参考文献；硬撑下去只会导致误读 |
| 方法描述含糊但有代码     | **继续 Pass 3** 并阅读实现                                   |
| 某个核心假设看起来不成立 | **停止** —— 质量不足以支撑更多时间投入                       |
| 结果看起来重要但证据单薄 | **继续 Pass 3**，专门针对该缺口做批判性审查                  |

## ⛔ 停止 —— 进入 Pass 3 的网关

**在任何 Pass 3 工作之前结束本回合。** Pass 3 耗时以小时计，必须由用户授权。

仅当论文足够相关，**且**满足以下之一时才建议进入 Pass 3：用户计划复现、依赖、扩展或严格评价它；它的主张会影响某个研究决策；或 Pass 2 暴露出后果重大的不确定性。说明网关决策、支撑证据，以及针对该目的**值得产出哪几项** Pass 3 交付物 —— 通常是一到两项，而不是全部。

获得授权后，先阅读 [references/deep-dive.md](references/deep-dive.md) 再开始。

## 交付形态

面向指令的文件本身用英文（`SKILL.md`），但**报告、表格和对话一律跟随用户使用的语言** —— 对中文用户就用中文。

开头先给出所请求的深度建议或答案；若存在红旗，红旗放在其之上。实质结论要带来源位置，三种证据标签要可区分，结尾给出当前深度下价值最高的下一步行动。根据用户既定目的调整标题和详略；**用户只要求一遍时，绝不输出三遍报告。**
