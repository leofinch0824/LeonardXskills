# Verify — 验证协议

验证不是独立阶段,是每个阶段的出口闸。本文件是全部验证协议的单一出处。

## 对抗复核(Synthesis 后,只对 T0/T1 抽取卡)

每篇 T0/T1 派一个 subagent:拿抽取卡回比对源文本(`.cache/` 里的解析 markdown 或 LaTeX 章节),逐字段打标:

- **grounded**:源文本直接支持
- **partial**:源文本部分支持,抽取有放大 → 在抽取卡该字段后标注"[部分外推]"
- **unsupported**:源文本找不到依据 → 记入复核报告

规则:unsupported > 0 → 回炉修正(见失败政策)。

## 完整性批判(Synthesis 后)

一个 subagent 只看 `02-pool.md` + `03-triage.md` + `05-synthesis.md`,回答三个问题:

1. 漏了哪篇奠基作?
2. 漏了哪个竞争方向?
3. 哪个 Intake 问题的答案最薄?

每个问题要么补检(回 Discovery,把补检的查询词和返回数追加进 02-pool.md 检索记录),要么记录"不补"的理由。

完整性批判还负责给**空结果作证**:各源查询词+返回数都在检索记录里,空结果才算"已充分检索",才能作为一等结果交付。

## 记分卡(写在 06-brief.md 顶部)

| 维度 | 算法 | 及格线 |
|---|---|---|
| 覆盖度 | 有答案或"未找到"标注的 Intake 问题数 / 总问题数 | 100% |
| 引用密度 | 挂 [paper-id] 的事实结论 / 全部事实结论 | ≥90%,其余标"推断" |
| 未支持声明 | 对抗复核 unsupported 条数 | 0 |
| 可操作性 | 每个痛点 ≥1 个前三档(直接可用/需微调/API 辅助)方案 | 布尔 |
| 完整性 | 完整性批判的问题有处置数 / 总问题数 | 100% |
| 校准度 | 人工抽审 2–3 篇 T1 的 overclaim 比例 | 交付后由用户回填 |

## 失败政策

回炉 ≤1 次:修 unsupported、补检批判发现的问题。仍不及格 → **带警告交付**:简报顶部标出未过闸维度+对应章节名。
不静默降级(藏失败比展示失败危险),不无限回炉(烧 token)。
