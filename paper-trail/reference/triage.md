# Triage — 分层规则

用廉价信号先过滤,只对 T0+T1 花精读成本。每条 T0/T1 的理由是三个月后的你唯一能读懂的东西。

## 信号表(按论文年龄分层加权)

| 信号 | 老论文(>24 个月) | 新论文(≤24 个月) |
|---|---|---|
| citationCount(S2 主,OpenAlex 后备) | 主信号 | 不用(天然近 0) |
| 被 survey 提及 / 进 taxonomy | 强正 | 强正 |
| HF Papers upvotes | — | 主信号 |
| S2 Recommendations 相关度 | 正 | 主信号 |
| snippet_search 正文片段匹配 | 正 | 正 |
| has-code(PwC / GitHub) | 正(可适用性强信号) | 正(可适用性强信号) |
| 与 Intake 原子问题的相关度 | 一票否决级 | 一票否决级 |

## 分层定义与名额

- **T0 奠基** ≤3:taxonomy 里绕不开的、方案路线依赖的。
- **T1 必读** ≤10:直接回答某个 Intake 原子问题。
- **T2 扫读**:可能有用,只读 abstract+TLDR,一行归类。
- **T3 跳过**:去重掉、不相关、质量明显不行,一行归类。

## 纪律

- T0/T1 每条写一句理由:**回答哪个原子问题 + 凭什么信号晋级**。
- 名额是预算纪律:超限时补晋级理由或降级,不扩名额。
- 新论文不因零引用被压:≤24 个月的论文按上行信号表的右列加权。
- 不为满足篇数而把低相关论文晋级到 T1。

## 论文池充分性

满足任一条件即标记`POOL_THIN`：

1. T0 + T1 合计少于 5 篇；
2. 任一 Intake 原子问题没有直接相关的 T0/T1；
3. 某个原子问题只有 `abstract-only` 或单一来源证据；
4. Discovery 因关键后端不可用而明显收缩，且未执行对应降级检索。

5 篇是触发补检的软阈值，不是交付硬下限。先如实分层，再判定充分性。

### 一次有界补检

`POOL_THIN` 只允许自动补检一次，并按顺序执行：

1. 使用 Landscape 衍生词重新查询；
2. 增加同义词或上位 taxonomy 节点；
3. 将近期窗口从 24 个月放宽到 48 个月，奠基作仍不限年代；
4. 对现有高相关论文执行前向/后向 Snowballing；
5. 把每个查询的词来源标为`补检`，记录返回数和新增有效候选数。

补检完成后重跑分层与充分性判定。若不再满足条件，状态为`resolved`；若仍然过薄但检索证据充分，状态为`accepted-thin`，并把原因和覆盖缺口带入 Brief。不得执行第二次自动补检。

## 闸门

- 所有 Intake 原子问题都有明确的候选覆盖情况。
- `POOL_THIN` 已补检一次，或论文池判定为`sufficient`。
- `accepted-thin` 已记录完整检索证据和交付警告。
- T0/T1 相关性与名额纪律均未因薄池而放松。
