# learn-loop：把十步学习方法论复刻成可校验的 Agent Skill

## Context

`docs/用_Claude_Codex_Workbuddy_10倍速学习任何知识.md` 描述了一套融合 STORM 与 Rahul 检索练习法的十步学习闭环（五视角 → 矛盾图谱 → 简报 → 同行评审 → 资源筛选 → 阶梯 → 2 小时核心 20% → 考试 → 费曼 → 速查表）。原文形态是十段可复制的提示词，存在三个问题使它无法稳定复现：

1. **五视角由单个 agent 顺序写出**，后写的视角以先写的为条件，产出的是被编排的分工而非被发现的分歧。第 2 步矛盾图谱因此拆到的是修辞，不是认知。
2. **"所有视角都同意的大概率是真的"这个推论只在独立同意时成立**。若五个视角一致却无人拿得出来源，那是模型先验在五个出口同时显形——表观置信度最高、可核查性最低，是最危险的失败模式。原文没有区分这两种一致。
3. **没有执行规范性的约束**：跳步、少给一个视角、考试只问三题就收尾、速查表缺检查清单，都不会被发现。第 8/9 步必须真人逐轮回答，一旦会话中断就前功尽弃。

本轮产出一个中文优先的 `learn-loop` skill：以并行独立 subagent + 分化取证渠道恢复视角的真实差异，以来源等级与共识分级让结论可证伪，以脚本硬校验 + SKILL.md 语义闸门约束每步规范性，并补上原文缺失的跨轮回顾环节。

仓库已有 `paper-trail/` 作为 skill 骨架范式（SKILL.md 定不变量与阶段闸门、`reference/` 渐进披露、`templates/` 每轮实例化、`scripts/preflight.py` 机器硬检查、stdlib unittest 锁契约、零第三方依赖）。**沿用其工程骨架，但不沿用其方法论**：paper-trail 的核心不变量是"论文存在性只由 API 决定"，服务于外部证据可追溯；learn-loop 的核心不变量是"视角独立性"与"检索练习真实发生"，服务于认知冲突的产生与知识的内化。

---

## 设计决策（已与用户确认）

| 决策 | 选择 |
|---|---|
| skill 边界 | 单一 skill 覆盖十步，run-state 落盘支持断点续跑与单步调用 |
| 规范性检查 | `scripts/validate_stage.py` 硬校验结构 + SKILL.md 承载语义闸门，两者互不替代 |
| 视角独立性 | 5 个并行独立 subagent，互不可见；主 agent 只分发与收集，不参与写作 |
| 取证方式 | 每个视角走自己的信息渠道；取不到时标注来源等级，不阻断 |
| 考试交互 | 逐题中断，每题落盘，可跨会话续考 |
| 跨轮回顾 | `learner-profile.md` + `review-queue.md`（1/7/30 天间隔重复） |

**依赖**：不引入任何第三方 Python 包，全部使用 stdlib（`argparse`/`json`/`pathlib`/`datetime`/`re`）。无需 `poetry add`。

## 一、核心不变量（写入 SKILL.md 顶部）

1. **视角独立性**：第 1 步的五个视角必须由五个并行 subagent 产出，彼此不可见对方的输出；主 agent 只做分发与收集。任何"由主 agent 一次性写出五段"的执行都视为未过闸。
2. **取证渠道分化**：每个视角按自己的渠道优先级取证并落盘检索记录（查询词 / 渠道 / 命中数 / 是否采信）。渠道不分化则 persona 只是语气差异。
3. **来源等级强制标注**：每条主张标 A/B/C 三级——
   - `A` 一手可核查：有可解析 URL 且直接支持该主张
   - `B` 二手或间接：有 URL 但为转述、或仅部分支持
   - `C` 模型内生·未验证：无来源
4. **共识必须分级**：≥2 个视角一致、各自引用**不同**来源且至少一条 A/B → 记为「独立共识」；一致但全为 C 级 → 记为「模型先验·待验证」，禁止进入简报的高可靠结论。
5. **盲区需以检索记录为前提**：「无人提及 X」只有在各视角检索记录已落盘时才可判为领域盲区，否则只能写「未覆盖」。
6. **检索练习不得代答**：第 8/9 步的回答只能来自用户。模型不得代填答案，不得因用户未答而自行推进题号。
7. **profile 只记录用户明确确认的长期事实**；模型从答题表现推断的倾向只写入本轮产物，不回灌 profile。

## 二、路径契约

沿用 paper-trail 的四锚点解析方式（见 `paper-trail/scripts/preflight.py:100` `resolve_workspace_root`、`:93` `resolve_path`，可直接改名复用）：

- `<skill-root>`：`SKILL.md` 所在目录
- `<workspace-root>`：显式参数 → `LEARN_LOOP_WORKSPACE_ROOT` → Git 根 → 当前目录
- `<state-root>`：`LEARN_LOOP_STATE_DIR`，默认 `<workspace-root>/.learn-loop`
- `<learning-root>`：`LEARN_LOOP_LEARNING_DIR`，默认 `<workspace-root>/learning`

派生：`<profile-path> = <state-root>/learner-profile.md`、`<queue-path> = <state-root>/review-queue.md`、`<index-path> = <learning-root>/INDEX.md`、`<run-dir> = <learning-root>/<YYYY-MM-DD>-<slug>`。

skill 包保持只读；`--bootstrap` 是唯一写操作，只创建缺失文件，不覆盖已有内容。

## 四、十步流程与闸门（SKILL.md 主体）

### 第 1 步 · 五视角（并行独立）

主 agent 起 5 个并行 subagent，每个只拿到「主题 + 自己的 persona + 自己的渠道优先级」。渠道分化按 `reference/perspectives.md`：

| 视角 | 渠道优先级 |
|---|---|
| 实践者 | 工程博客、issue tracker、事故复盘、从业者论坛 |
| 学者 | 同行评审论文、综述、会议录 |
| 怀疑者 | 复现失败报告、负面结果、撤稿与批评、对立立场长文 |
| 经济学家 | 融资与并购、定价与营收、市场规模报告 |
| 历史学家 | 相似先例的回顾性记述、行业史、失败案例分析 |

每个视角产出：核心立场（两句）、最强证据（带来源等级）、独家洞见、**检索记录表**（查询词 / 渠道 / 命中数 / 是否采信）。

**闸门**：恰好 5 个视角且各自完整；每个视角有检索记录；每条证据标了 A/B/C；主 agent 未参与写作。

> 检索工具不可用时整轮进入「未锚定模式」：全部证据记 C 级，`run-state.md` 标注，且第 3、4 步产物顶部必须声明。

### 第 2 步 · 矛盾图谱

由一个只读五份原始产物的 agent 完成。每条冲突先分类：

- **实质分歧**：双方各有 A/B 级来源且结论不兼容 → 进图谱
- **措辞分歧**：同一主张换说法 → 剔除，不计入冲突数
- **未决**：至少一方无来源 → 单独列出，标为待验证

产出：冲突项（双方依据 + 证据强弱判定）、关键裁决问题、共识分级表（独立共识 / 模型先验·待验证）、盲区（区分「领域盲区」与「未覆盖」）。

**闸门**：每条冲突已分类且实质分歧双方均引来源；共识已分级；盲区判定附各视角检索记录依据。

### 第 3 步 · 综合简报

60 秒 CEO 段落、5 个关键发现（按可靠性排序、标注支持/反对视角）、跨视角隐藏关联、面向用户角色的行动建议、前沿问题。

**闸门**：每个发现挂来源等级与支持视角；「模型先验·待验证」的共识不得出现在前 3 个发现中。

### 第 4 步 · 同行评审自检

可靠性 1–10 分**必须由来源等级与分歧类型推导**，不得凭感觉（推导规则写在 `reference/conflict.md`）。另需回答：最没把握的结论及验证所需信息、权重过大的视角、是否需要第 6 视角、斯坦福教授会打几分与改什么。

**闸门**：5 个发现逐个打分且每分附推导依据；第 6 视角问题已明确「需要 / 不需要」并给理由。

### 第 5 步 · 资源筛选

恰好 5 个资源，每个含：为何强于同类、怎么用（读/看/练）、耗时、要拿走的一个关键点。另列被高估的坑，并排成一周路径。

**闸门**：恰好 5 个且字段齐；高估清单非空或明确写「无」；一周路径覆盖全部 5 个资源。

### 第 6 步 · 学习阶梯

五级（完全初学者 → 基本理解 → 实际使用者 → 问题解决者 → 自信的实践者），每级 8 个字段（级别名称、应理解什么、掌握的样子、重点概念、里程碑、动手练习、常犯错误、自测问题）。

**闸门**：5 级 × 8 字段全非空。

### 第 7 步 · 2 小时核心 20%

先甄别撬动 80% 效果的概念并说明为何是核心，再排 10 次课，每次含学习目标 / 关键概念 / 动手练习 / 推荐资源（优先免费）/ 预期结果 + 5 道复习题，最后给一个终局小项目。

**闸门**：恰好 10 次课，每次 5 字段齐且各附 5 题；终局项目可验证。

### 第 8 步 · 考到崩溃（逐题中断）

一次只问一题，等用户回答后做四件事：0–10 打分、答对之处、确切差距、用简单语言重讲漏掉的部分。答得弱先追问再进下一题，答得好则加难。难度分档：1–3 初级 / 4–6 中级 / 7–8 高级 / 9–10 专家级。

每题回答后立刻把该行写入 `08-exam.md` 并更新 `run-state.md` 的考试游标 —— **这是跨会话续考的唯一依据**。重进 skill 时读游标，从下一题继续，不重问已答题目。

收尾给：最终得分、最强领域、最弱领域、简短复习计划、5 道终局挑战题。

**闸门**：10 题全部有用户真实回答与四件套反馈；难度分档正确；游标与已落盘行数一致；无模型代答。

### 第 9 步 · 费曼循环

输入是第 8 步得分 < 6 的弱项。先用 12 岁听得懂的话讲，让用户复述，只重教复述里含糊/跳步的部分，再让用户讲一遍，循环到解释简单、准确、完整为止。**用户讲清楚之前不进入新内容。**

**闸门**：每个弱项至少一轮完整「教 → 复述 → 定位缺口 → 重教 → 复述」；每轮有用户真实复述；结束状态为「已讲清」或显式记录的「仍未通过」。

### 第 10 步 · 一页速查表 + 回灌

速查表六件套：一句大白话定义、短条目形式的核心概念/规则/步骤、3–5 个真实场景例子、新手易错与易混点、"上场前"检查清单、5 道快问快答。

回灌：`<index-path>` 追加一行（日期 / slug / 主题 / 最终得分 / 最弱领域）；`<queue-path>` 按 1/7/30 天写入三个复习到期日；`<profile-path>` 只写用户明确确认的长期事实。

**闸门**：六件套齐；INDEX 与 review-queue 均已追加；profile 更新有明确用户依据。

### 复习模式（第二入口）

`python3 scripts/review_queue.py --due` 列出到期主题；复习只抽该主题历史弱项重考，结果回写队列并推进到下一间隔。

## 五、`scripts/validate_stage.py` 硬校验清单

纯 stdlib，解析 markdown 结构，`--stage N`（或 `--all`）+ `--json`，退出码非零表示未过。通用检查：必填章节存在、表格无空单元格、模板占位符（`<...>` / `TBD`）已替换。

| 步 | 机器可校验的硬约束 |
|---|---|
| 1 | 恰好 5 个视角；每个含核心立场/最强证据/独家洞见/检索记录四段；每条证据行有 A\|B\|C 等级 |
| 2 | 每条冲突标了 实质/措辞/未决；共识表每行标 独立共识\|模型先验·待验证；盲区标 领域盲区\|未覆盖 |
| 3 | 恰好 5 个关键发现，每个有来源等级与支持/反对视角 |
| 4 | 5 个发现各有 1–10 分且附推导依据行；第 6 视角段落非空 |
| 5 | 恰好 5 个资源 × 4 字段；一周路径含 5 个条目 |
| 6 | 5 级 × 8 字段全非空 |
| 7 | 恰好 10 次课 × 5 字段；每次课复习题恰好 5 条；终局项目段非空 |
| 8 | 恰好 10 行答题记录；每行有用户回答/得分/差距；难度分档与题号匹配；游标一致 |
| 9 | 每个弱项 ≥1 轮闭环；每轮含用户复述；结束状态为二值之一 |
| 10 | 六件套齐；快问快答恰好 5 条；INDEX 与 queue 已追加 |

语义判断（理由是否成立、是否虚假晋级、共识是否真独立、用户回答是否真实）留给 SKILL.md 闸门，脚本不做。

## 六、测试

新增 `tests/test_learn_loop.py`，沿用 `tests/test_paper_trail.py` 的写法（stdlib unittest、`Path` 常量、临时目录、无第三方依赖）：

1. **包契约**：`REQUIRED_SKILL_FILES` 清单齐；skill 内无安装机绝对路径；含 `<skill-root>`/`<workspace-root>`/`<learning-root>` 占位（对应 `tests/test_paper_trail.py:63`）
2. **markdown 契约**：SKILL.md 含 7 条不变量关键词（`独立共识`、`模型先验·待验证`、`未锚定模式`、`领域盲区`、`未覆盖`、`A/B/C`）；各模板含对应必填章节标题
3. **profile 可移植性**：默认 `learner-profile.md` 无个人化默认值、字段为中性占位（对应 `:80`）
4. **validate_stage 单测**：为每步各造一份合规 fixture 与一份违规 fixture（4 个视角、证据缺等级、9 次课、考试游标与行数不一致、快问快答 4 条等），断言退出码与 JSON 中的 violation 项
5. **review_queue 单测**：给定完成日期产出 1/7/30 三个到期日；`--due` 只列出到期项；推进后写入下一间隔；不覆盖已有历史行
6. **preflight CLI**：bootstrap 在空工作区创建 profile/queue/INDEX；二次运行不覆盖；`--json` 报告路径与能力；Git 根回退可用

验证命令：

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile learn-loop/scripts/*.py
python3 learn-loop/scripts/preflight.py --workspace-root /tmp/ll-test --bootstrap --json
python3 learn-loop/scripts/validate_stage.py --run-dir /tmp/ll-test/learning/<date>-<slug> --all --json
```

端到端验收：用一个真实主题跑完十步（第 8/9 步需用户参与），确认十份产物齐、`--all` 全过、INDEX 与 review-queue 已追加。
