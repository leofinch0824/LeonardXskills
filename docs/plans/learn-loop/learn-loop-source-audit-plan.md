# Learn Loop 来源支持性审计实施计划

**日期：** 2026-09-02　**状态：** 已实施。前置分析：执行流程中 78 个违规码全部检查形式、零语义核验——最大风险（A 级来源是否真支持主张）恰好无自动防线。本计划补上第一道语义闸门。

## 目标

让「A/B 来源等级」的定义可被机器复核：

- **A 级** = URL 实际抓取成功，且主张关键词与正文重合达标（直接支持的机器近似）。
- **B 级** = URL 链接存活（间接/转述支持只承诺链接可解析）。
- **C 级** = 不审计（无 URL）。

## 形态：`scripts/audit_sources.py`

独立审计工具，不进 `validate_stage`（校验器保持离线、确定性）；它自己抓取并把机器可读报告写到 `context/source-audit.md`，校验器只读报告字段。

- 解析五份 `perspectives/*.md` 的`最强证据`（主张/URL/等级）与`检索记录`（采信 URL）。
- 抓取：stdlib urllib，超时与字节数上限，HTML 剥标签为文本；PDF/超时/反爬 →`未核验`（不构成发现，如实记录）。
- 重合度：主张提取关键词（CJK 二元组过滤停用字 + 拉丁/数字 token，上限 24 个），正文子串匹配，`命中/总数`。
- 发现（阻塞）：A 级链接失效或重合不足 →`建议降级`；B 级链接失效。修复闭环：A→B/A→C/换源后重跑审计即清零。
- 网络全不可用启发式：所有 URL 均无法连接时，无法区分死链与断网 → 全部记`未核验·网络不可用`，不产生发现（诚实降级，不造成离线死锁）。
- 跨角色域名分布（`registrable domain` 近似）：同一 URL 或同一母站被多角色引用 → 报告`提示`段（非发现，供步骤 2 独立性判定消费；官方文档被多视角合理引用是合法场景）。

## 闸门接线

`_validate_stage_1`：`锚定模式 = anchored` 时要求 `context/source-audit.md` 存在且`未决发现： 0`（违规码 `AUDIT_MISSING` / `AUDIT_UNRESOLVED`）；未锚定模式全链 C 级，不要求报告。`prepare_stage --stage 2` 依赖阶段 1 通过，闸门自动生效。

## 边界声明

重合度是关键词启发式，不能证明语义支持；审计结论列为交付边界中的用户复核项。学位域表为最小近似，不追求完整 public suffix 列表。

## 验证

- 本地 HTTP 服务单测：通过 / 建议降级 / 链接失效 / B 级存活 / 网络不可用 / 域名提示 / 降级后重跑清零。
- 闸门三态：anchored 无报告拒、未决非零拒、未锚定免检。
- 全套 pytest + CLI 冒烟（含审计闭环）。
