# Learn Loop 格式契约缺口分析与最终设计规范

> 状态：最终设计规范已落地（2026-08-05；实现进度见 `learn-loop-format-contract-remediation-plan.md`，验证边界见 `learn-loop-format-contract-eval-results.md`）
> 适用范围：`skills/learn-loop/`、其专用测试与 Learn Loop 运行目录
> 历史实证：`learning/2026-08-04-215937-emotional-regulation-cognitive-reframing/` 的 DeepSeek V4 Flash 实战产物
> 兼容策略：只实现本文最新契约，不迁移、不兼容此前测试运行目录

## 1. 结论

本次 32 项 Markdown 违规的主要原因不是模型完全没有执行任务，而是 Learn Loop 同时存在四套互不对齐的隐含规范：`SKILL.md`、参考文档、Markdown 范本和验证器。执行模型看不到范本，验证器却把范本形状当作唯一合法输出；部分验证规则还与原始提示词或锚定模式互相矛盾。

最终方案不是简单地“把所有范本提前复制出来”，而是建立阶段契约和渐进式披露机制：每次只给执行者当前阶段的原始提示词原文、阶段契约、当前范本和允许消费的上游；验证器只执行已披露的契约；Markdown 是唯一事实源，HTML 在构建时读取 Markdown 并展开跨文件引用。

目标是让中高能力模型把注意力用于内容判断，让格式、顺序、状态和引用由明确契约与脚本约束，同时不把所有叙事内容压成僵硬表单。

## 2. 已验证缺陷

### 2.1 契约不可达

- `templates/*.md` 定义精确文件名、标题和字段，但 `SKILL.md` 与 `reference/*.md` 没有指向这些范本。
- `preflight.py` 只检查部分范本存在，不把阶段范本交给执行者。
- 执行者按自然 Markdown 写作，验证器按未披露的精确正则校验，导致合理内容被拒绝。

### 2.2 验证器包含隐藏且脆弱的语法要求

- `### 关键发现 1`、`### 资源 1` 等标题被要求恰好结束于数字，但文档未说明。
- 字段只能用内联 `- **字段：** 值`，自然使用的子标题或近义标签全部失败。
- 中文标题使用 `\b` 计数，数字后直接接汉字时误判。
- `消费上游`用模糊文本切片和反引号搜索，布局变化后会静默漏检。
- 错误以字符串堆叠，无法稳定定位到文件、记录和字段，诱发整篇重写。

### 2.3 语义契约相互矛盾

- 步骤 2 的互斥状态被验证器错误要求同时出现。
- 未锚定模式要求全部为 C，但步骤 3 又无条件要求前三项为 A/B。
- 原始提示词要求“五个视角全部同意”，纪律文件却把“两视角同意”也叫共识。
- 步骤 9 的静态“最终定义”与真实费曼循环终点重复，并把预判用户困惑误当作实际诊断。
- 模式 A 范本提前创建答题/复述记录，与“只保存真实交互”冲突。

### 2.4 状态存在重复事实源

- `run-state.md` 在多个章节重复独立性档位和锚定模式。
- 考试游标与弱项同时出现在 `run-state.md` 和考试记录中。
- HTML 状态、Markdown 记录和浏览器本地状态的职责边界不够清晰。

### 2.5 多 agent 协议会丢失信息

让角色 agent 只返回消息中的结构化片段，会丢失完整分析、失败检索和未决问题。正确做法是每个角色只写自己的正式文件，父 agent 在同步屏障后验证、汇总和渲染；角色文件永久保留，不用消息摘要代替。

### 2.6 测试没有成为可交付契约

`tests/test_learn_loop.py` 在工作区存在，但当前未被 Git 跟踪。历史计划依赖它，实际 skill 包却无法携带这些回归测试。新实施必须先把测试变成正式受版本控制产物，再进行任何 skill 行为修改。

## 3. 设计目标与非目标

### 3.1 目标

- 原始提示词逐字保留，维持系统设计意图和溯源价值。
- 每阶段只有一个最终可执行语义契约。
- 范本与验证器不存在未披露的隐藏字段或隐藏数量。
- 执行者一次只读取当前阶段所需上下文。
- 多 agent 完整落盘并可局部返工。
- 锚定与未锚定模式均能完成流水线，且措辞不会夸大证据。
- Markdown 可续跑、可引用、可验证；HTML 为静态离线视图。
- 结构校验严格，但自由叙事保留表达空间。

### 3.2 非目标

- 不迁移旧运行目录，不提供 v1/v2 分支。
- 不让脚本判断来源是否真的支持主张、分歧是否实质或用户原话是否真实。
- 不把每段内容都改造成字段表单。
- 不修改 `reference/original-prompts.md` 的原文。
- 不把 HTML 或浏览器本地状态提升为事实源。

## 4. 契约权威层级

| 层级 | 唯一职责 | 不得承担 |
|---|---|---|
| `reference/original-prompts.md` | 原始设计意图和逐字溯源 | 运行时字段规范、状态机 |
| `reference/stages/*.md` | 当前阶段的最终可执行语义契约 | Markdown 具体序列化、跨阶段总编排 |
| `templates/*.md` | 文件名、固定标题、字段标签、列表形状 | 创造阶段语义 |
| `SKILL.md` | 触发条件、总编排、阶段顺序、模式切换、完成标准 | 重复每阶段字段表 |
| `scripts/validate_stage.py` | 契约的只读可执行镜像 | 自动修复、隐藏规则、内容真实性判断 |
| `reference/html-guide.md` | HTML 视图与交互契约 | 生成新的事实内容 |

同一要求只能有一个权威定义。其他文件只能引用或执行它，不能维护近义副本。

## 5. 运行数据流与渐进式披露

```text
前置判定
  → preflight.py（工作区、全局状态、能力实测）
  → prepare_stage.py --stage 0（创建 run-state.md）
  → prepare_stage.py --stage N（验证 N-1、生成当步上下文包、复制当步范本）
  → agent 只消费当步上下文包并写当前产物
  → validate_stage.py --stage N（只读验证）
  → ...
  → finalize_run.py（全量验证、构建 HTML、登记索引/复习队列、收口状态）
```

### 5.1 阶段入口

唯一准备入口：

```bash
python3 <skill-root>/scripts/prepare_stage.py \
  --run-dir <run-dir> \
  --stage <0-10> \
  [--batch <1|2>] \
  --json
```

- 阶段 0 只创建未填的运行状态范本；初始内容经阶段 0 校验后，控制字段只由脚本推进。
- 阶段 N 必须重新验证 N-1 和运行状态；正常推进只允许游标 `N-1 → N`，同阶段重试允许停留在 N，步骤 7/8 的批次 2 只允许在本阶段游标上开始。
- 已有阶段产物不覆盖；同阶段重试复用既有字节，内容冲突时返回结构化错误。
- 不生成、不披露未来阶段的上下文。
- 步骤 7/8 使用两批：批次 1 为 1–5，批次 2 为 6–10；第二批只有在第一批局部校验通过后才披露。
- 每阶段生成自包含的 `context/stage-N.md`；它是披露快照，不是新的事实源。
- context 中的 `run-state.md` 摘录只保留稳定的运行、判定、画像和能力信息；易变的“模式 A 进度/上下文披露记录”仍只从原文件读取，不复制进包。
- `消费上游`仍列原始 Markdown 事实文件，context 包只保存被允许的精确摘录。

### 5.2 原始提示词保护

- 阶段包从 `original-prompts.md` 逐字截取对应章节。
- 测试证明摘录是当前原文件的连续原文片段。
- `run-state.md` 保存当前原文件 SHA-256，用于溯源，不用固定摘要阻塞未来合法更新。
- 本次实施以 Git diff 明确验证原文件未发生修改。

## 7. 通用 Markdown 序列化

- 重复记录使用纯结构编号标题，名称和内容不得拼接到标题后。
- 普通字段统一为 `- **字段名：** 值`。
- 多行字段值使用后续缩进行，直到下一个字段或标题。
- 固定章节使用阶段契约规定的标题；不接受近义字段别名。
- `本步提炼`在步骤 1–10 中恰好三条，分别承担核心结论、证据/边界/风险、下一步影响。
- 模式 B/C 记录不是模式 A 阶段产物，不强制添加“本步提炼”。
- 跨文件引用使用 ``相对路径#精确标题``，例如 ``03-brief.md#关键发现 1``；解析器限制路径位于运行目录并要求标题唯一。
- 空集合只在契约明确允许时写 `无：<可核查理由>`；裸写“无”不算完成。
- 验证器只读，不自动修复。错误对象至少包含 `code`、`file`、`record`、`field`、`expected`、`actual`、`message`。

## 8. 阶段 0：运行状态契约

`run-state.md` 是模式 A 控制状态的唯一事实源。练习游标和弱项不写入此文件。

### 8.1 运行标识

固定六字段：`运行 ID`、`创建时间`、`主题`、`运行目录`、`原始提示词文件`、`原始提示词 SHA-256`。

- 运行 ID 就是稳定 slug 和 HTML `data-run-id`。
- 创建时间为带时区 ISO 8601。
- 原始提示词文件使用逻辑相对路径，摘要按当前 UTF-8 字节计算。

### 8.2 前置判定

固定四字段：`判定`、`判定理由`、`调整说明`、`资料探针`。

- 已创建运行目录时，判定只能是`适合`或`调整后适合`。
- 适合时调整说明为`无需调整`。
- 调整后适合时，同一字段记录调整、风险和用户确认原话。
- 资料探针只写`未做`或`已做：<结论>`，不产生来源等级。

### 8.3 学习画像

固定五字段：`当前水平`、`目标深度`、`角色 / 使用场景`、`画像句`、`默认处理`。

- 前三字段只能以`用户回答：`、`用户开场已提供：`或`未提供`开头。
- 用户授权默认时使用：零基础、能上手干活、普通学习者 / 个人实践。
- 未缺失时写`默认处理：无需默认值`；未授权默认且有缺失时阻塞步骤 1。

### 8.4 能力与降级

固定五字段：`独立性档位`、`子 agent 验证依据`、`锚定模式`、`检索验证依据`、`降级声明`。

- 独立性档位枚举：`parallel`、`serial-isolated`、`orchestrated`。
- 锚定模式枚举：`anchored`、`未锚定模式`。
- 未实测不得写“不可用”；未验证时按相应降级模式执行。
- 可实际读取并验证的本地用户资料也可以构成 anchored，不限于互联网搜索。

### 8.5 模式 A 进度

固定三字段：`当前阶段`、`已完成阶段`、`生成状态`。

- 当前阶段为 0–10 或`完成`。
- 已完成阶段只能是从 0 开始的连续区间。
- 生成状态为`进行中`或`已完成`。
- 校验失败不创造“失败”状态，只保持当前阶段并返回错误。

### 8.6 上下文披露记录

每个已准备阶段恰好一条追加记录，仅含`准备时间`和`披露清单`。清单逐项标明原始提示词、阶段契约、当前范本、允许消费上游、context 包和角色任务包；无项写`无`或`不适用`。步骤 7/8 第二批在同一阶段记录中追加披露路径。

### 8.7 删除重复练习状态

- `08-exam-record.md`唯一保存考试游标、待回答项和弱项。
- `09-feynman-record.md`唯一保存复述轮次和结束状态。
- 文件不存在表示相应模式未启动；HTML从记录文件存在性和内容推导状态。

## 9. 步骤 1：五视角独立取证

### 9.1 调度

- 五个角色 agent 各自只读取自己的自包含任务包，并只写自己的正式角色文件。
- 不并发写 `run-state.md`、`01-perspectives.md` 或其他角色文件。
- `parallel`与`serial-isolated`使用完全相同的任务包和合并协议，只改变调度。
- `orchestrated`保留五个隔离文件，但步骤 2 必须声明分歧可信度降级。
- 父 agent 等五份文件全部到齐后形成同步屏障；失败只退回对应角色。

### 9.2 单角色文件

1. `核心立场`：恰好两个编号句。
2. `最强证据`：`证据主张`、`来源 URL`、`来源等级`、`支持说明`；C 级额外填写`未锚定原因`。
3. `独家洞见`：`洞见内容`、`为何属于该视角`、`适用边界`。
4. `视角分析`：自由 Markdown，保存主张、反例和限制，不要求隐藏思维过程。
5. `检索记录`：至少一条；每条为`查询词`、`检索渠道`、`结果状态`、`来源 URL`、`取舍理由`。状态枚举为`采信`、`未采信`、`未命中`、`检索不可用`；不再要求不可靠的“命中数”。
6. `未决问题`：1–3 项，或`无：理由`。

A/B 必须有可解析 URL；C 的 URL 为`无`。未锚定模式下全部证据为 C。

### 9.3 父级汇总

`01-perspectives.md`按实践者、学者、怀疑者、经济学家、历史学家的固定顺序抽取核心立场、最强证据、独家洞见和未决问题，并引用角色文件。完整分析和检索记录只保留在角色文件中。验证器比较汇总值与角色文件，防止父 agent 悄悄改写。

## 10. 步骤 2：矛盾图谱

### 10.1 分歧记录

每条固定七字段：`涉及视角`、`立场 A`、`立场 B`、`依据引用`、`分类`、`分类理由`、`需要的验证`。

分类枚举：

- `实质分歧`：结论不兼容且两边都有 A/B。
- `措辞分歧`：核心结论相同，仅范围、术语或语气不同。
- `未决`：至少一方缺 A/B，或来源不能直接支持结论。

不强制每类都出现；没有任何可成立分歧时允许精确空声明。

### 10.2 证据强弱比较

固定八字段：`比较范围`、`最强视角`、`最强证据引用`、`最强理由`、`最弱视角`、`最弱证据引用`、`最弱理由`、`比较限制`。未锚定模式必须说明强弱只表示论证相对完整度，不表示事实可靠性。

### 10.3 关键裁决问题

有实质或未决分歧时恰好一个，字段为`问题`、`对应分歧引用`、`为何能化解`、`所需证据`、`判定方式`、`不同答案的影响`；没有可裁决分歧时明确为空。

### 10.4 全体一致与局部一致

- `全体一致`必须有五个支持视角。
- `局部一致`有 2–4 个支持视角。
- 两组可以同时出现，但同一结论不得重复归类；局部一致不得冒充原始提示词中的全体共识。

每条一致结论固定八字段：`结论`、`支持视角`、`未支持或反对视角`、`证据引用`、`综合来源等级`、`来源独立性说明`、`分级`、`成立边界`。分级只能是`独立共识`或`模型先验·待验证`。

### 10.5 盲区判定

只保留最高影响候选或明确为空。字段为`候选遗漏`、`判定`、`未提及依据`、`检索完整性依据`、`为什么重要`、`下一步验证`、`表述边界`。判定只能是`领域盲区`或`未覆盖`；即使为前者，也只能表述为当前五视角取证形成的候选判断。

## 11. 步骤 3：综合简报 / 假设简报

- anchored 输出“综合简报”；前三个关键发现必须为 A/B。
- 未锚定模式输出“假设简报”；五个发现允许全 C，整体声明模型先验，禁止使用“独立共识”“证据最强”等已取证措辞。
- `60 秒 CEO 总结`保持一个连续自由段落，语义覆盖核心结论、最可靠依据、最大不确定性和角色行动含义；脚本不限制字数。
- 恰好五个关键发现，每条字段为`发现`、`证据引用`、`综合等级`、`支持视角`、`反对视角`；无反对视角时写`无：理由`。
- `隐藏关联`保留自由文本，不拆字段；内容评审检查是否真正综合五视角。
- `行动建议`保留自由文本，必须代入角色/场景、引用关键发现并给出可观察完成信号。
- `前沿问题`保留自由文本，必须说明答案为何会改变整体理解。

## 12. 步骤 4：同行评审

每个发现评审只保存对步骤 3 的引用，不重复抄写发现正文：

- `发现引用`
- `可靠性分数`
- `推导依据`
- `所需验证信息`

五项综合自检：

- 最没把握：发现引用、原因、验证信息。
- 过重视角：视角、造成的影响。
- 第 6 视角：候选视角、会改变的发现引用、改变原因；没有时必须给可核查理由。
- 教授评分：模拟评分、主要修改意见，不能伪装成真实教授背书。

Markdown 保持引用规范化；构建 HTML 时，渲染器读取步骤 3 和步骤 4，将发现正文与评审信息展开为同一张完整卡片。最终 HTML 是静态、自包含视图，浏览器不再读取 Markdown 文件。

## 13. 步骤 5：资源筛选

### 13.1 五张资源卡

恰好五项，每项九字段：`资源名称`、`资源类型`、`来源 URL`、`来源等级`、`为什么比同类强`、`画像适配理由`、`使用方法`、`预计耗时`、`关键收获`。

- A/B 必须有 URL。
- C 的 URL 为`无`，并在比较理由中明确模型先验与缺失锚定。
- 资源类型自由填写，不维护封闭枚举。
- 画像适配只消费用户已提供或已授权默认的信息。

### 13.2 被高估的坑

允许 0–3 项；无可靠依据时明确为空。每项字段为`对象或做法`、`风险原因`、`适用边界`、`依据引用`、`替代做法`，不得把对当前画像不适合夸大为普遍无价值。

### 13.3 一周路径

包含 5–7 个按第 1–7 天排序的行动节点，五项资源各引用至少一次。每个节点字段为`时间`、`资源引用`、`具体动作`、`完成证据`。总耗时必须与资源卡和画像相容；放不进一周时缩小使用范围，不虚构可完成性。

## 14. 步骤 6：学习阶梯

固定五级，每级八字段：`级别名称`、`应该理解`、`掌握表现`、`重点概念或技能`、`里程碑`、`动手练习或小型项目`、`常见错误`、`自测问题`。

`当前级与下一里程碑`固定为`当前级别`、`判断依据`、`下一里程碑`。掌握必须以可观察或可运行结果判断，不以阅读时长代替。

## 15. 步骤 7：两小时核心 20%

- 恰好 10 课，每课恰好 5 道复习题。
- 批次 1 生成 1–5，局部验证通过后批次 2 生成 6–10，再做整体覆盖检查。
- 每课六字段：`课程名称`、`学习目标`、`关键概念`、`动手练习`、`推荐资源`、`预期结果`。
- 核心 20% 保留清单式自由文本，每项必须同时说明“是什么”和“为什么核心”，不强制人为数量。
- 终局小项目四字段：`输入`、`动作`、`可检查输出`、`完成标准`。

## 16. 步骤 8：主动回忆题库

- 先生成十行覆盖计划：题号、概念、认知动作、难度。
- 恰好 10 道基础题：1–3 初级、4–6 中级、7–8 高级、9–10 专家级。
- 每题六字段：`题干`、`难度`、`参考答案`、`满分标准`、`及格标准`、`常见薄弱点`。
- 批次 1 生成 1–5，批次 2 生成 6–10；合并后检查概念覆盖、认知动作重复和难度递进。
- 恰好 5 道终极挑战，只给题干；挑战区不得出现答案或评分标准。
- 模式 A 不创建考试记录。

## 17. 步骤 9：费曼备教材料

步骤 9 回归“解释—复述—定位缺口—重讲”的费曼循环，不在模式 A 伪造用户理解。

### 17.1 12 岁版讲解

- 一段简单但准确的自由讲解。
- 恰好两个生活例子；每个字段为`场景`、`对应关系`、`例子边界`。

### 17.2 复述检查点

恰好 3–5 项，每项字段为`必须讲清`、`可接受的简化`、`错误或跳步信号`、`对应重讲`。

这些检查点是开放式诊断工具，不是对用户弱项的预判清单。模式 C 必须先检查用户真实复述，不能因为措辞没有命中预写列表就宣告通过或失败。

### 17.3 删除模式 A 最终定义

- 步骤 9 不再生成“最终定义”。
- 费曼终点是模式 C 最后一轮通过的用户逐字复述。
- 步骤 10 的一句定义是压缩和检索提示，不是费曼掌握证明。

这一设计符合教学促发自解释与检索练习的核心作用：学习者必须主动生成解释并暴露知识缺口，而不是只阅读模型给出的最终表述。参考：[Caltech 教学促进学习说明](https://ctlo.caltech.edu/aboutctlo/whoweserve/undergraduates/learning-resources/learning/power-of-teaching)、[Chi 等人的自解释研究](https://doi.org/10.1207/s15516709cog1302_1)、[Roediger 与 Karpicke 的检索练习研究](https://pubmed.ncbi.nlm.nih.gov/16507066/)。

## 18. 步骤 10：一页速查表

固定六个标题：

1. `一句大白话定义`
2. `核心要点`
3. `实际应用场景`
4. `易错与易混`
5. `上场前检查清单`
6. `快问快答`

- 核心要点用一条一个意思的短列表，不复制长篇简报，不强制隐藏数量。
- 实际应用场景为 3–5 个真实使用情境，不用抽象比喻代替应用。
- 快问快答恰好 5 题，每题恰好一个答案。
- 一句定义是五分钟回看用的压缩提示，不宣称替代真实复述。
- `回灌记录`不再放在速查表事实内容中；索引、复习队列和可选 profile 更新由最终化脚本负责并独立验证。

## 19. 模式 B：真实施考记录

- 模式 A 不创建 `08-exam-record.md`；首次真实触发时才从范本创建。
- 会话状态字段：`当前游标`、`待回答项`、`结束状态`。
- 当前游标只表示已完整完成的基础题数，范围 0–10。
- 发题或追问前先写`待回答`块，保存所属题号、类型和实际提问；用户未答时不推进游标。
- 完成的基础题事务字段：`难度`、`实际提问`、`用户回答逐字引用`、`得分`、`答对处`、`确切差距`、`简语重讲`。
- 追问嵌套在基础题下，保存同组实际交互字段，不增加游标。
- 五道挑战在基础题完成后逐题进行，单列挑战记录，不增加基础题游标。
- 完成记录只追加，不覆盖；待回答块允许原子更新。
- 十道基础题完成后写基础题总分、强项、弱项和复习计划；低于 6 分的弱项供模式 C 消费。

## 20. 模式 C：真实费曼复述记录

- 模式 A 不创建 `09-feynman-record.md`；首次真实触发时才创建。
- 会话状态字段：`当前概念`、`已完成轮次`、`待回答项`、`结束状态`。
- 发出教学和复述邀请前先写待回答块；用户未复述时不增加轮次。
- 每轮事务字段：`本轮教学`、`复述邀请`、`用户逐字复述`、`含糊或跳步处`、`只重教缺口`、`下一步`。
- 讲清前继续同一概念，不隐式切换。
- 结束状态只能是`进行中`、`已讲清`或`仍未通过`；已讲清必须引用最后一轮真实逐字复述。
- 用户停止时允许仍未通过，不用模型代写一轮“正确复述”收尾。

## 21. HTML 构建与引用展开

- Markdown 仍是唯一事实源。
- `render_learning_page.py`读取并先验证 Markdown，再生成已填充 HTML。
- `render_template.py`继续只负责固定 CSS/JS 的复制或内联，不承担事实提取。
- Markdown 转 HTML 在构建时完成，禁用原始 HTML，所有文本和 URL 安全转义。
- 步骤 1 在 HTML 中展示五视角摘要，并以折叠区展开各角色完整文件。
- 步骤 4 的`发现引用`在构建时解析步骤 3，组合成“发现正文 + 来源/视角 + 评审分数/理由”的完整卡片。
- 浏览器打开最终文件时不再请求 Markdown；链接资源模式只依赖同目录 `template.css` 和 `template.js`，`--inline`生成物理单文件。
- 模式 B/C 状态由记录文件推导，浏览器本地三态自评不回写 Markdown。
- 保留当前工作区已经加入的短主标题 + 非空副标题结构及相应 HTML 校验。

## 22. 最终化与外部回灌

`finalize_run.py`按以下事务顺序执行：

1. 验证阶段 0–10；
2. 构建 HTML；
3. 验证 HTML；
4. 按运行 ID 幂等追加 `INDEX.md`；
5. 按运行 ID 幂等登记 1/7/30 日复习；

任一步失败都不得提前写完成状态。重复执行不得产生重复索引或复习队列行。

### 23.2 父 agent 内容评审

- 分歧分类是否合理；
- 来源是否直接支持主张；
- 评分推导、资源比较和课程递进是否合理；
