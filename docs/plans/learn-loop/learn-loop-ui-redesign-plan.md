# Learn Loop 学习产物 UI 重设计计划

> 状态：**已实施**（2026-08-04）
> 计划对象：`skills/learn-loop/assets/template.html`、`template.css`、`template.js` 及其渲染契约
> 事实样例：`learning/2026-08-04-005557-agent-harness-claude-code-workbuddy/Agent-Harness-设计与实现-十步学习.html`
> 视觉规范：`brand-spec.md`

## 1. 意图摘要

把 Learn Loop 当前的“章节式文档门户”升级为高密度但易读的“证据驱动学习工作台”。重设计不改变十步生成顺序、Markdown 事实源、A/B/C 来源分级与模式 A/B/C 的信任边界；它要显著改善长文阅读、信息扫描、学习导航、主动回忆和证据核查，并在桌面与移动端都形成清晰、可持续的学习路径。

本计划定义本轮实现所需的设计、交互和验收标准，并作为模板优化的验收基线。

## 2. 设计依据与不可变约束

从 `skills/learn-loop/SKILL.md` 与 `reference/html-guide.md` 提取以下系统原则，作为任何视觉决策的上位约束：

1. **事实源与视图分离**：Markdown 是事实源，HTML 只负责呈现，不在视图层补写结论或用户表现。
2. **先结论、后论证**：阅读顺序保持“学习地图 → 10 → 7 → 6 → 9 → 8 → 1–5 → 收尾”，不可机械恢复为生成顺序。
3. **双层信息架构**：本步提炼、可视化和正文默认可见；提示词与上游放在默认收起的取证层。
4. **主动回忆优先**：题目必须先作答再展开答案，自评只发生在答案展开后。
5. **状态边界不可混淆**：本机已读/自评、真实施考记录、费曼复述记录是三类不同事实，视觉上也必须区分。
6. **证据可追溯**：A/B/C 来源等级、支持/反对视角与未锚定声明必须可扫描、可核查。
7. **可留存、可复习**：打印、无 JavaScript 降级、搜索、响应式与本地状态不可因重设计退化。

## 3. 当前风格诊断

### 3.1 已有风格资产

当前模板使用深海军蓝固定侧栏、冷灰画布、纸白内容面和金色强调；Georgia 用于标题，系统无衬线用于正文。整体稳重、可信、低干扰，符合研究资料的基础气质。侧栏导航、学习地图、深色“本步提炼”、折叠取证和闪卡组件已经形成初步产品语言。

这些资产应保留：

- 深海军蓝承担全局导航和权威感；
- 纸白阅读面与冷灰背景形成清楚的内容边界；
- 金色继续作为稀缺焦点色；
- 标题与正文使用不同字体角色；
- “教学内容默认可见、证据默认收起”的层级关系。

### 3.2 核心风格缺陷

| 严重度 | 缺陷 | 当前表现 | 影响 |
|---|---|---|---|
| P0 | 页面类型与内容类型不匹配 | 十个章节几乎复用同一组 `.takeaways + .viz + .prose + details` | 五视角、矛盾图、课程阶梯、题库等不同任务被压成同一种长文，学习动作不突出 |
| P0 | 内容密度失控 | 样例 HTML 超过 5,800 行；第 1 步单个视图约占 2,000 行 | 用户无法判断当前位置、已读范围和下一步动作 |
| P0 | 标题系统不适配中文长标题 | `h1` 最小 42px、最大 76px，且中文回退并不真正使用 Georgia | 长主题易形成大面积多行标题，拉低首屏信息效率；中英文字形气质不一致 |
| P1 | 卡片化过度且语义不足 | `.card`、`.panel`、`.takeaways`、`.viz` 都是相近的边框圆角容器 | 视觉上“块很多、层级少”，重点依靠包框而非排版建立 |
| P1 | 正文阅读列过宽 | 页面容器可达 1,040px，`.prose` 无独立阅读宽度 | 16px 长段落行长偏大，CEO 摘要、方法解释等连续文本难以阅读 |
| P1 | 深色高亮区使用机械 | 每章固定出现大块深色“本步提炼” | 重复十次后失去稀缺性，也让每章视觉开头过重 |
| P1 | 可视化是空泛插槽 | `.viz` 只是通用容器，样例中甚至出现 `.viz` 内再嵌 `.card` | 容器套容器，没有真正形成冲突图、阶梯、证据矩阵等信息图形 |
| P1 | 状态组件仍是装饰式警示条 | `.status` 使用左侧金色边框与淡黄底 | 与证据等级、提醒、系统状态难区分，也形成常见模板化视觉 |
| P2 | 字体角色只对拉丁字符成立 | Georgia 不含中文字形；中文标题回退到系统字体 | “展示字体 ≠ 正文字体”的设计意图在中文内容中失效 |
| P2 | 强调色和状态色缺少统一语义 | CSS 中额外散落绿色、红色、黄色等原始十六进制 | 品牌一致性弱，后续扩展容易形成颜色漂移 |

## 4. 排版与内容渲染问题

### 4.1 标题层级

- 章节页同时出现“第 N 步” kicker 与标题中的“第 N 步：…”，信息重复。
- `h2`、`h3`、`h4` 主要只靠字号变化；长章节中连续多组 `h3 + h4 + ul` 很难建立分组边界。
- 中文 kicker 仍使用大字距和大写转换的西文规则，视觉收益有限。
- 标题没有显示“本章预计阅读时间、内容结构、当前状态”等帮助定位的信息。

**改法**：标题区改为“阶段标签 + 精简标题 + 一句目的 + 本章元信息”；标题本身不重复步骤编号。桌面标题控制在 2 行内，移动端使用更小的 `clamp()` 下限。长章节标题后提供页内目录或结构摘要。

### 4.2 正文段落

- `.prose p` 统一使用 10px 下边距，长文段间关系过于平均。
- 没有阅读列宽约束，正文、表格、证据卡都占同一宽度。
- 关键句主要依赖 `<strong>`，在高密度段落里无法形成扫读锚点。
- 样例中的 CEO 总结、关键发现、行动建议、前沿问题都以普通正文方式连续呈现，内容角色没有视觉差异。

**改法**：正文阅读列控制在约 64–70 个中文字符的视觉宽度；段落组之间使用 24–32px 节奏。允许表格、关系图、练习区跨出阅读列。为“执行摘要、关键发现、行动建议、前沿问题”定义不同但克制的语义版式，不靠新增颜色堆叠。

### 4.3 高亮与摘要区域

- “本步提炼”每章都是整块深色卡，既抢占首屏，又无法表达条目优先级。
- A/B/C 证据等级目前主要藏在正文句子中，不能快速比较。
- 重要结论、风险、未验证声明、下一步动作缺少统一标记体系。

**改法**：把“本步提炼”重构为章节摘要带：一个主结论 + 3–5 个短要点，桌面可使用 2 列，移动端单列。深色只用于章节主结论或全局未锚定声明，不再整块包裹所有摘要。证据等级使用紧凑的单字母徽标和文字说明，不能只用颜色编码。

### 4.4 列表、表格与证据

- 多层无序列表连续出现，关键发现之间缺少独立边界。
- 表格虽然可横向滚动，但移动端只是“能看”，没有优先级重排。
- 来源链接以长列表收尾，来源等级、支持视角与主张的关系不够直观。

**改法**：

- “五个关键发现”使用编号发现条目，每项固定为“结论 / 可靠性 / 支持与反对 / 为什么重要 / 来源”。
- 宽表在移动端转换为纵向记录卡或优先列视图，而非单纯横向滚动。
- A/B/C 标签与来源标题放在同一视觉单元，URL 作为次级信息；外链显示明确的外部打开提示。
- 代码、提示词与技术标识统一用等宽字体，避免与普通正文混杂。

## 5. 交互逻辑问题

| 严重度 | 问题 | 原因 | 计划修复 |
|---|---|---|---|
| P0 | 没有连续学习路径 | 章节只能从侧栏/地图跳转，正文末尾没有“上一章/下一章/回到地图” | 每章末尾加入学习导航，并显示推荐下一步而非数字下一步 |
| P0 | “考我/我来讲”像可点击能力，实际需回到对话触发 | 状态文案是命令句，页面内没有动作与上下文解释 | 改为外部工作流卡：说明将在对话中继续，提供“复制提示词”按钮，不伪装成站内施考 |
| P0 | 学习状态含义不够清楚 | “已读”“已掌握”“施考完成”同时存在，但视觉关系弱 | 建立三层状态模型：阅读进度、本机练习、真实会话记录；分区展示且用明确文案说明来源 |
| P1 | 侧栏顺序与 1→10 编号冲突 | 阅读顺序按教学价值重排，但界面只显示章节组名 | 增加“推荐学习路径”标识，并把“生成步骤编号”降为元数据 |
| P1 | 长章节缺少章内定位 | 单个 `.view` 可能包含几十个标题和长表 | 桌面增加粘性章内目录；移动端使用折叠“本章目录” |
| P1 | 搜索只返回每章第一个命中且无结果上限/分类 | 当前索引按 view 聚合，片段只取首次命中 | 结果按标题、正文、来源分类；显示命中计数并限制首屏结果，支持“查看本章全部命中” |
| P1 | 本地状态键不稳定 | 使用 `document.title` 作为 localStorage 命名空间 | 下一版渲染提供稳定 run id；旧数据迁移或保持兼容，不因标题修改丢失状态 |
| P1 | 练习只有“答对/答错”二元判断 | 无“模糊/稍后复习”，也没有空筛选提示 | 使用“掌握 / 模糊 / 未掌握”三态；弱项筛选包含后两者并提供清空筛选 |
| P2 | 桌面折叠按钮和移动菜单触控面积不足 | 多个按钮只使用 6–9px 内边距 | 所有交互目标至少 44px；键盘焦点与 hover/active 状态完整 |
| P2 | 响应式只有一个 900px 断点 | 移动端只是隐藏侧栏并缩小 padding | 分别设计手机、平板与桌面结构；手机提供底部“目录/搜索/进度”入口，不挤压桌面布局 |
| P2 | 侧栏折叠只在首次加载时按媒体查询创建 | 窗口跨断点变化时控件生命周期不完整 | 监听断点变化并统一管理抽屉/折叠状态；折叠偏好可持久化 |

## 6. 选定的 UI 方向

### 6.1 方向名称

**证据驱动的学习工作台（Evidence-led Learning Workbench）**

它不是营销页，也不是普通知识库。视觉上结合三种角色：

- **编辑阅读器**：窄正文列、中文衬线标题、强段落节奏，让长篇内容可持续阅读；
- **研究工作台**：稳定导航、证据等级、来源关系和可核查状态清楚可见；
- **主动回忆训练器**：题目、答案、自评、弱项与下一次行动形成闭环。

### 6.2 为什么适合 Learn Loop

1. SKILL 的核心不是“展示十步”，而是“可追溯、可校验、可复习”；工作台比文档门户更能表达状态和动作。
2. 第 1–5 步是研究取证，第 6–7 步是课程与实践，第 8–10 步是检索、讲解和压缩；单一文章版式无法同时服务三类任务。
3. 用户是研发、用于个人学习与产品设计，信息密度可以高，但必须提供明确路径和快速回到上下文的能力。
4. 现有深海军蓝与金色具备可信、克制的基础，不需要推翻品牌，只需把容器式布局升级为语义式布局。

### 6.3 视觉系统

- 使用 `brand-spec.md` 的六个核心 OKLch 令牌；深海军蓝为导航辅助面。
- 中文标题使用宋体类展示栈；正文使用苹方/系统无衬线；数字、证据等级与代码使用等宽字体。
- 一个视口中金色高权重用法不超过两处，默认是当前导航焦点和主动作。
- 减少圆角卡片，统一为三类表面：阅读面、操作面、证据面。不同语义不靠任意彩色边框区分。
- 只保留一个决定性视觉亮点：章节顶部的“证据路径线”，把本章结论、来源等级和下一学习动作串成一条可扫描路线。

## 7. 页面结构与组件计划

### 7.1 全局框架

桌面采用三层框架：

1. 240–264px 全局导航：主题、推荐路径、章节状态、搜索入口；
2. 680–760px 主阅读列：标题、摘要、正文、练习；
3. 可选 220–280px 上下文栏：章内目录、来源等级、下一动作；窄桌面时自动收起。

第三栏采用桌面响应式折叠：宽桌面显示上下文栏，窄桌面自动收起。本轮只优化桌面浏览器体验；既有小屏内容可达性与无 JavaScript 降级不得退化，但不新增移动端专属布局或导航模式。样式与折叠逻辑全部固化在模板资源中，不增加 skill 运行时上下文负担。

### 7.2 章节通用骨架

每章统一采用以下顺序：

1. 阶段标签、章节标题、用途与状态；
2. 章节摘要带：主结论、关键要点、证据概况；
3. 本章结构导航；
4. 章节专属内容模块；
5. 默认收起的“取证 · 提示词与上游”；
6. 阅读完成与推荐下一步。

### 7.3 章节专属模块

| 步骤 | 主要组件 | 关键交互 |
|---|---|---|
| 学习地图 | 推荐路径、十步分组、当前进度、能力边界说明 | 继续上次、按推荐路径开始、查看全部步骤 |
| 10 速查 | 定义、清单、易错对照、快问快答 | 勾选清单、展开答案、三态自评 |
| 7 课程冲刺 | 时间轴、核心 20%、终局项目、每日任务 | 按阶段展开、标记计划完成，不伪装为真实能力掌握 |
| 6 学习阶梯 | 五层阶梯、当前层、下一里程碑 | 聚焦当前层，展开详细描述 |
| 9 费曼 | 讲解层级、常见混淆、对话交接卡 | 复制“给我讲/我来讲”提示词 |
| 8 自测 | 题目、难度、答案、评分标准、弱项队列 | 洗牌、三态自评、仅看弱项、重置本机自评 |
| 1 五视角 | 五个 persona、证据计数、立场对照 | 按视角/来源等级筛选，跳到具体来源 |
| 2 矛盾图 | 共识、实质分歧、未决问题关系图 | 按分歧类型筛选，展开双方证据 |
| 3 综合简报 | CEO 摘要、五个发现、行动建议 | 发现折叠/展开，证据快速核查 |
| 4 同行评审 | 可靠性评分、最弱结论、缺失视角 | 评分依据展开，不把模型评分表现成客观真值 |
| 5 资源筛选 | 资源卡、适用对象、优缺点、一周路径 | 按来源等级/用途筛选，外链明确提示 |
| 收尾 | 产物清单、复习节奏、下一轮入口 | 复制复习命令、返回学习地图 |

## 8. 状态与数据模型

下一轮实现需要明确区分以下数据域：

| 数据域 | 来源 | 是否写回事实源 | UI 表达 |
|---|---|:---:|---|
| 章节已读 | 浏览器本地状态 | 否 | “阅读进度”，可撤销 |
| 闪卡自评 | 浏览器本地状态 | 否 | “本机练习”，三态并附边界说明 |
| 模式 B 施考 | `08-exam-record.md` | 是 | “真实施考记录”，仅按渲染时事实显示 |
| 模式 C 费曼 | `09-feynman-record.md` | 是 | “复述记录”，不得由模型自证通过 |
| 复习计划 | review queue / run state | 是 | “下次复习”，只读显示，更新由既有脚本负责 |

建议在不改变 Markdown 事实源前提下，引入稳定的渲染级 `data-run-id`，用于本地状态命名空间；是否新增占位符需同步更新 guide、validator 与测试，不能只改模板。

## 9. 文件级实施计划

### 阶段 A：结构与视觉基础

1. 更新 `brand-spec.md`，确认最终令牌与中文字体栈。
2. 重构 `assets/template.html` 的页面区域和章节骨架，保留现有阅读顺序与取证折叠。
3. 重构 `assets/template.css`：建立六个核心令牌、排版尺度、三类表面、响应式布局和完整焦点状态。
4. 在所有可评论的页面区域、标题、控制和重复模块上补唯一 `data-od-id`。

### 阶段 B：内容渲染语义

1. 为五视角、矛盾图、学习阶梯、关键发现、资源卡和练习卡定义语义片段。
2. 更新 `render_template.py` 或其输入装配逻辑，使 Markdown 内容进入正确组件，而非全部落入通用 `.prose`。
3. 更新 `reference/html-guide.md`，记录每种内容模块、空态、长标题、表格和证据等级的渲染契约。
4. 确保 STEP OUTPUT 仍从事实源生成，HTML 不补写事实。

### 阶段 C：交互闭环

1. 增加章内目录、上一章/下一章、继续上次学习和推荐下一步。
2. 把闪卡改为三态自评，补空筛选、重置和键盘操作。
3. 改进搜索结果结构、命中计数和章内定位。
4. 增加稳定 run id、本机状态迁移与侧栏偏好持久化。
5. 为模式 B/C 增加明确的对话交接卡与复制提示词动作，不伪造站内会话能力。

### 阶段 D：闸门与回归

1. 扩展 `validate_stage.py --stage html`，覆盖关键区域、状态边界、重复 id、未折叠答案、未锚定声明和本地资源。
2. 扩展 `tests/test_learn_loop.py`，覆盖新模板契约、稳定状态键、三态自评、搜索、响应式结构和无 JS 降级。
3. 使用真实长主题、长表格、长链接、全中文标题和中英混排建立视觉回归样例。
4. 执行一次最终预览，检查重叠、裁切、横向溢出、触控目标和打印结果。

## 10. 响应式与无障碍验收

- 桌面重点验收 1024、1280、1366、1440、1600、1920px；窗口缩窄时第三栏先收起，侧栏随后切换为既有抽屉降级。
- 360–820px 仅守住现有内容可达、无页面级横向滚动与抽屉可用，不在本轮新增移动端专属设计。
- 所有按钮、菜单、summary 和主要链接触控目标至少 44px。
- 键盘可完成导航、搜索、展开答案、自评、筛选与关闭抽屉；焦点顺序与视觉顺序一致。
- 所有焦点状态清晰；颜色不是状态的唯一表达；正文与背景、控件与背景满足 WCAG AA 对比度。
- `prefers-reduced-motion` 下关闭非必要过渡；搜索定位不依赖闪烁才能理解。
- 无 JavaScript 时所有正文、答案和证据可达；打印时完整展开且不打印交互控件。
- 长标题不覆盖导航或上下文栏；正文不超过阅读列；表格值不溢出单元格。

## 12. 范围外事项

- 不改变十步学习法本身、步骤数量或事实源文件结构。

- 不引入第三方前端框架、外部字体 CDN 或远程图片依赖。
- 不在本轮重写现有学习内容；重设计只改变结构化呈现和交互。
